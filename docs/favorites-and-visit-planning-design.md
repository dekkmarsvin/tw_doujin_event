# 收藏與走訪規劃模組設計

## 目的與範圍

本模組把「記住感興趣的社團」與「安排活動當天怎麼走」連成可回顧的流程，但保留兩者的語意邊界。收藏是長期偏好與備註的容器；行程、下一站與已走訪是特定活動中的執行狀態。

P0 使用瀏覽器本機儲存，不要求登入或跨裝置同步。資料模型與元件不得依賴特定儲存方式，以便 P2 加入帳號同步時不重寫產品語意。

## 責任邊界

- `FavoritesRepository` 是收藏與群組的唯一讀寫 seam；清單卡、完整詳情與地圖不得各自保存 `isFavorite`。
- `VisitPlanRepository` 保存活動內的行程狀態與順序，不因收藏切換而自動新增或移除項目。
- 頁面 controller 把 repository 狀態投影到社團清單、詳情與 `AccessibleEventMapRenderer`；renderer 只呈現狀態並回報互動。
- UI 元件負責顯示與收集意圖，不直接理解 localStorage key、序列化版本或未來帳號 API。

## 領域模型

```ts
type FavoriteRecord = {
  eventId: string;
  circleId: string;
  groupId: string | null;
  memo: string;
  createdAt: string;
  updatedAt: string;
};

type FavoriteGroup = {
  id: string;
  label: string;
  color: string;
  sortOrder: number;
};

type VisitStatus = "planned" | "next" | "visited";

type VisitPlanEntry = {
  eventId: string;
  day: string | number;
  circleId: string;
  status: VisitStatus;
  routeOrder: number;
  updatedAt: string;
};
```

### 不變量

- `FavoriteRecord` 以 `eventId + circleId` 唯一；記錄存在即代表已收藏，不另存 `isFavorite`。
- `FavoriteGroup.label` 去除前後空白後必須非空；顏色可重複，且不得作為群組識別鍵。
- 同一攤位的多個社團以不同 `circleId` 建立獨立收藏與備註，不因 booth code 相同而合併。
- 刪除收藏群組前必須讓使用者選擇移到其他群組或變成未分類，不得連帶靜默刪除收藏。
- 同一活動最多一筆 `status = "next"`；設定新的下一站時，原下一站回到 `planned`，不得取消其收藏。
- `routeOrder` 只對同一活動的行程項目有意義；收藏列表排序不得反向改寫行程順序。
- 已取消或不存在的社團資料保留使用者收藏與備註，介面標示資料狀態並允許移除或匯出。

## 儲存與版本

- P0 以 versioned local storage document 保存，例如 `{ schemaVersion, groups, favorites, visitPlans }`；讀取時先驗證與遷移，再提供給 UI。
- 寫入使用單一 repository transaction 或等效原子更新，避免群組、收藏與行程在多個 key 之間部分成功。
- `circleId` 是關聯鍵；社團名稱、攤位與圖片不複製進收藏資料，顯示時從目前 `CircleRecord` 解析。
- 當社團在不同日期或區域有不同配置時，行程以 `eventId + circleId` 解析對應 `PlacementRecord`；找不到配置時顯示「目前無可用攤位」。
- P0 的復原用匯出包含 schema version、群組、收藏、備註與行程；不得包含瀏覽歷程或不必要的外部服務憑證。匯入與衝突寫入仍保留到 P2。
- 「清除所有規劃資料」必須先列出收藏、備註與行程的受影響數量並再次確認；完成後不得留下無法管理的孤兒群組或行程項目。

## 核心互動

### 收藏

1. 使用者在清單、詳情或地圖側欄切換收藏。
2. 首次收藏立即建立 `FavoriteRecord`，預設為未分類，並顯示可選的群組與備註入口。
3. 修改群組或備註後，所有介面立即反映相同結果。
4. 取消收藏後顯示七秒 Undo；復原使用移除前的完整 `FavoriteRecord`，包括群組、備註與時間欄位，且不改變行程。

### 收藏分類

- 每個分類同時顯示名稱與色彩；色彩只協助掃讀，不承擔語意。
- 使用者可新增、改名、改色、排序與刪除分類。
- 篩選結果顯示群組名稱與項目數；空群組仍可管理，但不製造無內容卡片。

### 走訪規劃

- 「加入行程」建立 `planned`；「設為下一站」建立或更新為 `next`；「標為已走訪」更新為 `visited`。
- 收藏不是加入行程的前提，加入行程也不強制收藏；介面可以在同一規劃區呈現兩者，但動作標籤必須分開。
- 使用者可拖曳調整 `routeOrder`，並保留鍵盤可用的往前／往後按鈕；每次移動後順序壓縮為 0 起始連續整數。使用者亦可跳過或移除行程項目；移除行程不刪收藏、群組或備註。
- 地圖用形狀、圖示與文字輔助顯示 planned、next、visited，不只使用顏色。

## 跨介面一致性

| 操作來源 | 必須同步的介面 |
| --- | --- |
| 社團清單收藏 | 完整詳情、地圖 slot、地圖側欄、收藏清單 |
| 詳情修改群組／備註 | 清單收藏提示、地圖側欄、收藏清單 |
| 地圖設為下一站 | 行程清單、所有對應地圖狀態、社團詳情 |
| 行程調整順序或標為已走訪 | 行程清單、地圖 slot、地圖側欄 |

同一分頁內使用共享 store 或訂閱；多分頁使用 `storage` event、`BroadcastChannel` 或等效機制。同步失敗時以明確狀態提示，不以最後一次渲染的局部狀態覆寫 repository。

## P0、P1、P2 邊界

- **P0：** 本機收藏、具名稱群組、備註、加入行程、下一站、已走訪、跨介面同步，以及復原用途的版本化 JSON／CSV 安全匯出；不提供匯入介面。
- **P1：** 已完成拖曳調整路線、群組批次操作、含備註收藏的可靠 Undo 與活動當日快速模式。展場模式只把地圖暫時投影為當日行程、聚焦下一個未完成目標並顯示完成／剩餘數，不清除原搜尋與篩選資料，也不進行 GPS 或自動路徑推算。
- **P2：** JSON／CSV 匯入與衝突寫入、登入後跨裝置同步、分享規劃與協作清單。導入前需另行定義隱私、衝突解決與刪除政策。

## 驗收條件

- 任一介面收藏社團後，其他已開啟介面不需重新整理即可看到相同收藏、群組與備註。
- 收藏分類在所有位置都有文字名稱；關閉色彩後仍能辨識。
- 取消含備註的收藏不會無提示地遺失使用者輸入。
- 設定新下一站只改變同活動的行程狀態，不新增、移除或重新分類收藏。
- 重新載入後可恢復 P0 資料；格式升版後舊資料可遷移或安全匯出。
- 外部社團內容失效時，收藏、備註與行程仍可讀取、編輯及移除。
- catalog 找不到對應社團時，管理介面仍可看見未匹配收藏／行程的 ID、備註或狀態並個別移除；匯出必須保留原記錄。
- 清除全部資料前可看見受影響數量，取消確認不會改變任何資料。
- P2 匯出後在空白瀏覽器環境匯入，可還原群組、收藏、備註與行程，並回報無法匹配的社團。

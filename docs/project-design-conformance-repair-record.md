## 已確認的進階搜尋決策

### 問題

目前 `DisplayFilterControls` 使用「進階篩選與顯示」名稱，但其資料只有：

- 收藏群組
- 行程狀態
- 結果排序
- 資訊密度
- 每筆媒體數量

這些條件的共同用途是管理「我的規劃狀態」與「結果如何顯示」，不是搜尋社團內容。把它們放在名為進階搜尋的入口下，會讓使用者預期可以依作品、題材或標籤找社團，實際卻看到收藏管理條件。

目前頂部自由文字搜尋已把攤位代碼、社團名、作者、類別、作品、介紹及標籤串成一段文字查詢，因此能偶然搜到題材；但它沒有欄位範圍、主題候選、包含／排除條件、分級或原創／二創等結構化控制，也無法清楚說明命中原因。

### 名稱與責任拆分

#### 1. 進階搜尋

「進階搜尋」只處理社團及作品內容的搜尋意圖，第一版至少包含：

- 搜尋範圍：全部、社團／作者、作品／原作、題材／標籤。
- 主題條件：可選一個以上作品、原作或題材標籤。
- 排除主題：排除不想看到的作品或題材。
- 創作屬性：全部、原創、二創；資料不明時不得自行推定。
- 分級：全部、一般、R18；同時標成多種分級或資料不明時須保留原始狀態，不可靜默改寫。
- 創作類別：沿用現有繪圖、Cosplay、VTuber、手作等類別；桌面與手機不得建立不同語意。
- 已套用條件摘要、逐項清除、全部清除與命中結果數。

日期、區域及主要創作類別可繼續保留在常駐側欄；進階搜尋重點是內容主題，不應重複製造第二套日期或場館模型。

#### 2. 規劃篩選

下列條件改名並歸入「規劃篩選」：

- 只看收藏
- 收藏群組
- 行程狀態

這些條件只投影使用者規劃資料，不得改寫社團或作品資料。

#### 3. 顯示設定

下列條件歸入「顯示設定」：

- 結果排序
- 資訊密度
- 每筆媒體數量

顯示設定不得改變搜尋結果集合；只允許改變順序或呈現密度。

### 搜尋資料前置修復

目前 `tags` 含有尾端空白、逗號合併值與「R18, 一般」等複合字串。進階搜尋不可在元件中即時猜測或切割這些字串。應先建立可測試的正規化搜尋投影，例如：

```ts
type CircleSearchFacets = {
  circleId: string;
  circleNames: string[];
  creators: string[];
  works: string[];
  topics: string[];
  genres: string[];
  originality: "original" | "derivative" | "unknown";
  ratings: Array<"general" | "r18" | "unknown">;
};
```

- 搜尋投影由資料匯入／catalog 層建立，UI 只消費已整理好的 facets。
- 正規化只用於搜尋與聚合；原始名稱、標籤及來源值仍須保留。
- 同義作品名稱可加入明確 alias，但不得以模糊名稱自動合併不同主題。
- facet 必須以修復後的穩定 `CircleRecord.id` 為鍵，不以攤位代碼作為社團身分。

### 進階搜尋互動契約

1. 使用者開啟進階搜尋時看到目前已套用的搜尋條件，不看到收藏群組或行程狀態。
2. 面板內修改先保存為草稿；按「套用搜尋」後才更新結果與 URL。
3. 按「取消」或關閉時捨棄未套用草稿。
4. 套用後在結果區上方顯示每個條件的文字 chip，並可逐項清除。
5. 空結果保留原搜尋條件，顯示造成零結果的條件並提供逐項或全部清除。
6. 重新整理、分享 URL 與瀏覽器上一頁可恢復已套用條件；尚未套用草稿不寫入 URL。
7. 結果卡需能說明主要命中欄位，例如「符合主題：蔚藍檔案」，避免使用者無法理解結果來源。
8. 鍵盤開啟後焦點進入面板；Tab 不得移到被遮住的背景控制，Escape 關閉後焦點回到觸發按鈕。

### 進階搜尋驗收條件

- 搜尋「蔚藍檔案」可限定只匹配作品／原作，不因社團介紹中的偶然文字造成難以解釋的結果。
- 可同時指定兩個主題並依明確的 AND／OR 規則取得結果；介面必須顯示目前採用的規則。
- 排除主題後，結果與條件摘要同步更新。
- 選擇 R18 時只回傳明確具有 R18 facet 的社團；資料不明不得視為 R18 或一般。
- 切換資訊密度、媒體數量或排序不改變結果 ID 集合。
- 收藏群組或行程狀態不再出現在「進階搜尋」面板，但仍可與搜尋條件組合使用。
- 桌面與手機使用相同搜尋狀態、URL 及結果集合。

## 修復項目

### R1：分離加入行程與下一站

- 優先級：P0／阻斷設計符合性
- 現況：`addToVisitPlan()` 在當日沒有下一站時，把新增項目建立為 `next`。
- 需求：加入行程一律建立 `planned`；只有「設為下一站」可建立或轉移 `next`。
- 驗收：第一次加入行程後顯示「待前往」，且下一站提示不會出現；按「設為下一站」後才切換。
- 測試：補上第一次加入、已有下一站、移除下一站與標為已走訪的狀態轉移測試。

### R2：建立穩定社團身分與多攤位配置

- 優先級：P0／資料模型
- 現況：每筆攤位列產生獨立 `circleId`，相同社團的相鄰或跨日攤位不會共用收藏與備註。
- 需求：人工核對或具有穩定識別證據後，一個 `CircleRecord` 可連到一筆以上 `PlacementRecord`；同名但無證據的資料仍不得自動合併。
- 驗收：同一社團的多個攤位從任一介面收藏後，其他配置顯示相同收藏、群組及備註；真正不同的同名社團仍保持分離。
- 遷移：提供舊 placement-scoped ID 到新 `circleId` 的版本化遷移，不得靜默丟失本機規劃資料。

### R3：重建進階搜尋資訊架構

- 優先級：P0／核心探索流程
- 現況：收藏群組、行程、排序與密度被包在「進階篩選與顯示」中。
- 需求：依本文件「已確認的進階搜尋決策」拆成進階搜尋、規劃篩選及顯示設定。
- 驗收：使用者點「進階搜尋」後，第一屏直接看到社團主題／作品／標籤條件；收藏管理條件不在其中。

### R4：補齊收藏群組的跨介面呈現

- 優先級：P0／規劃一致性
- 現況：搜尋卡與地圖側欄只有收藏圖示，未顯示群組名稱。
- 需求：已分組收藏在清單卡、完整詳情、地圖側欄及收藏清單都顯示文字群組名稱；色彩只能輔助。
- 驗收：停用色彩後仍能辨識每筆收藏所屬群組；修改群組不需重新整理即可同步。

### R5：補齊地圖狀態的可讀名稱

- 優先級：P0／基本無障礙
- 現況：SVG slot 的 `aria-label` 只有攤位、社團與類別，沒有收藏、待前往、下一站或已走訪狀態。
- 需求：可互動 slot 的可讀名稱包含所有目前狀態；視覺標記與文字狀態由同一投影產生。
- 驗收：螢幕閱讀器可讀出「A03、MAI、已收藏、下一站」等組合，狀態變更後即時更新。

### R6：修復對話框焦點生命週期

- 優先級：P0／基本無障礙
- 現況：規劃資料對話框開啟後焦點仍停在背景觸發按鈕，部分面板也缺少焦點圈限與焦點復原。
- 需求：開啟後聚焦標題或第一個適當控制；Tab／Shift+Tab 留在 modal 內；Escape、關閉按鈕或遮罩關閉後焦點回到原觸發按鈕。
- 驗收：只使用鍵盤即可完成開啟、瀏覽、取消及回到原位置；被遮住的背景控制不可取得焦點。

### R7：收斂 P2 匯入匯出分期

- 優先級：決策阻斷
- 現況：一般介面已提供 JSON／CSV 匯入匯出與衝突選項，但正式模組文件仍將它列為 P2。
- 需求：在下列方案中擇一並同步所有正式文件：
  - 接受提前實作：把它標示為已完成的 P2 子項，補齊隱私、衝突與刪除政策。
  - 維持原分期：暫時隱藏匯入入口，只保留可恢復性所需的安全匯出。
- 驗收：`PRODUCT.md`、`DESIGN.md`、收藏模組與資料來源模組對匯入狀態沒有矛盾。

### R8：建立可重現的交付基線

- 優先級：P0／工程交付
- 現況：README 仍是 starter 文件；lint 因 `@ts-nocheck` 失敗；主要文件與實作尚未形成提交基線。
- 需求：更新產品 README、移除或收斂 `@ts-nocheck`、通過 build／test／lint，確認資料與生成檔納管邊界後建立提交。
- 驗收：新環境依 README 可啟動與取得地圖；所有 gate 通過；工作區只保留明確說明的本機資料或生成物。

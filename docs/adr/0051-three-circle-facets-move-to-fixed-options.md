# ADR-0051：創作者類型、作品類型與年齡分級改為固定選項

- **狀態**：Accepted
- **日期**：2026-09-08
- **延續**：[ADR-0030](./0030-organizer-category-catalog-circle-selected-value.md) 把 `circleCategory` 收斂到主辦分類目錄的作法
- **不變更**：[ADR-0025](./0025-open-with-an-official-only-thin-catalog.md) 的薄目錄——這三個欄位的值仍然只由社團自己填寫，主辦 base 不提供
- **相關文件**：[社團自助控制面契約](../contracts/circle-portal.md)、[搜尋、篩選與顯示設定契約](../contracts/search.md)、[URL 檢視狀態契約](../contracts/url-state.md)

## 背景

社團可填的五個清單欄位裡，只有 `circleCategory` 有目錄，其餘全是自由文字：輸入框、以逗號分隔、驗證只看筆數與長度。實際結果是同一件事會有很多種寫法，搜尋要拿它們當條件就得靠猜。

`workTypes` 的情況更明確：公開端詳細搜尋的「原創／二創」條件用的是它，而且是**完全比對**。這個條件從上線到現在沒有任何資料在用——薄目錄不提供，社團也沒有理由剛好打出那兩個詞。

## 決策

### 1. 三個 facet 只能從固定選項挑

`creatorTypes`、`workTypes` 與 `ageRatings` 的可選值寫在 `app/circle-overrides.ts`，與 `LINK_KINDS` 同一個位置、同一個理由：編輯器不得提供這份檔案會拒絕的值。`referencedWorks` 與 `specialTags` 仍是自由填寫——那兩個欄位講的是作品本身，沒有可以事先窮舉的清單。

搜尋面板讀同一份常數，因此「社團填得出來的值」與「讀者篩得到的值」不可能對不上。

**基數**：`creatorTypes` 與 `ageRatings` 可複選（核取方塊），`workTypes` 選一項（下拉選單）。

`ageRatings` 可複選是這份 ADR 在合併前修訂的一點——初稿寫的是「各選一項」。理由是單選在這個欄位上不只是介面較窄，它會**刪掉資料**：`ageRatings` 描述的是販售內容，同時出全年齡本與 R18 本是真實而且常見的，而單選在作者下次動到分級時會把另一個值一起換掉，等於替社團改了它沒說要改的事。搜尋端本來就以 `.some()` 逐值比對，這樣的社團查「全年齡」與查「R18」都會命中，不需要另外處理。

`workTypes` 維持單選：取向講的是這個社團面向誰，混合的情況用「一般向」表達；若日後實際遇到必須同時標男性向與女性向的社團，再回來改這一條。

閱讀端要不要從多值推導出單一的「最高限制分級」，是另一件事，不在這份 ADR 內（[#193](https://github.com/dekkmarsvin/tw_doujin_event/issues/193)）。

### 2. 寫入驗證不做成員檢查

`isCircleOverrideFields` 維持只檢查筆數與長度。它同時是讀取端守門：`parseCircleOverridesPayload` 會把不合格的 override **整列**丟掉。若在這裡收緊，一個帶著舊值的欄位會讓該社團的販售資訊、連結與縮圖一起從公開文件消失——為了詞彙一致而讓內容消失，是把代價放在錯的地方。

收斂靠編輯器的選項清單。既有的舊值在編輯器裡照原樣列出並勾選，作者看得到也刪得掉，下次編輯自然換成新詞彙。

### 3. 作品類型改成取向，搜尋條件跟著改

`workTypes` 的選項是男性向／女性向／一般向，詳細搜尋的條件同步改成同一組；URL 的 `workType` 由 `original`／`derivative` 改為 `male`／`female`／`general`。原創與二創的區分改由主辦分類目錄（`circleCategory`）與作品／題材承接。

舊連結帶的 `original`／`derivative` 沒有對應的取向，讀到就視為未設定：只掉這一個條件，其餘參數照常解析。不保留對應是因為兩組詞彙講的不是同一件事，硬對到任何一個取向都是猜測。

### 4. 年齡分級的值就是畫面上的字

選項是「全年齡」與「R18」，資料裡存的就是這兩個字，`circleIncludesGeneral` 的規則加上「全年齡」。不採「畫面寫全年齡、資料存一般」的作法：日後看 D1 或匯出資料的人不必再翻一次對照表。

R15 與未設定仍然兩邊都不匹配，[搜尋契約](../contracts/search.md)的「分級不推測」不變。

## 後果

- 三個 facet 的新資料收斂到固定詞彙，搜尋條件從此有東西可篩。
- `ageRatings` 的多值在閱讀端目前就是照原樣列出（「分級：全年齡、R18」）。要不要改成顯示推導出的最高分級，等 #193。
- 既有的自由文字值不會消失也不會被自動改寫，只在編輯器裡顯示為額外選項，等作者處理。
- 寫入端與讀取端的詞彙一致性沒有機器把關，只有編輯器把關。若日後 API 開放給社團以外的寫入者，這個決策要重看。
- 詞彙清單改動會同時影響控制面與公開搜尋，是一處改、兩處生效。

## 未決

- 選項不足時（例如 R15、或清單外的創作者類型）目前沒有「其他」選項，社團只能不填。要不要開放，等實際遇到再決定——先開反而會把剛收斂完的詞彙重新打散。R15 正式成為第三級分級的規劃在 #193。
- `workTypes` 是否也該可複選，等實際資料。

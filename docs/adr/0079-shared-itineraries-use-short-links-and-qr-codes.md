# ADR-0079：本場行程以短網址與 QR Code 分享，同一流程帶到自己的手機

- 狀態：已定案（2026-10-03，#415 維護者決策）。
- 相關：[ADR-0002](./0002-planning-data-stays-on-device.md)（規劃資料留在裝置）、[ADR-0078](./0078-own-planning-backups-can-be-imported.md)（完整備份與復原）
- 相關契約：[收藏與走訪規劃契約](../contracts/planning.md#分享行程)、[URL 檢視狀態契約](../contracts/url-state.md)

## 脈絡

讀者要把電腦上排好的本場行程帶到現場的手機，也想把挑好的攤位推薦給朋友。兩者都不該要求一般使用者操作 JSON 檔，也不能連同私人備註、群組、購買項目與預算一起送出。系統不需要分辨接收者是不是分享者本人。

曾考慮把清單直接塞進 URL fragment、過長再改用分享檔；這讓使用者面對兩種分享方式，QR Code 密度也隨攤位數增加，因此不採用。

## 決策

**帶到自己的手機與分享給朋友是同一條流程：建立精簡 snapshot，取得短網址 `/s/<shareId>`，可複製、系統分享或顯示 QR Code。**

- **snapshot 只有** schema 版本、活動 ID、社團 ID、必要的活動日與順序。不保存群組、私人備註、購買項目、預算、下一站／已走訪、帳號或 email、社團名稱與攤位號、瀏覽紀錄。社團名稱、目前攤位與移動／退出狀態一律在開啟時由最新公開資料解析，snapshot 不成為社團或配置的資料權威。
- **後端只做三件事**：建立匿名 snapshot、依不可猜測的 ID 讀取、到期刪除。不做會員、編輯、同步、永久連結、自訂 slug、分享統計或 QR 圖片保存。到期時間為活動結束後 30 天，由既有 retention purge 刪除，不新增排程。刪除前的過期連結顯示已過期並可返回該活動；刪除後不保留任何資料，與不存在的連結一樣顯示「不存在或已過期」並連到活動選擇頁。
- **濫用防護**：只接受已發布活動、`c-<數字>` 社團 ID 與該活動的日期，最多 500 項；每個 IP 雜湊每小時有建立上限。不加 Turnstile，分享不多一步。
- **QR Code 只編碼短網址**，在前端即時繪製，不保存圖片、不新增圖片 API；QR 程式只在開啟分享時載入。
- **社群預覽**：`/s/<shareId>` 由伺服器回應含活動名稱與項目數的 `og:title`／`og:description`，圖片固定為品牌分享圖 `/share-card.png`，不使用活動圖、不動態產生圖片。
- **接收端先看唯讀預覽**，不寫入。按「加入我的行程」才寫入：在分享日期仍有攤位的社團加入該日行程（待前往，接在既有順序之後）；已存在的保留，不覆寫備註、購買項目、預算、下一站／已走訪或順序；已移動、已退出、找不到的列出並略過。

## 後果

- 「資料管理」的完整備份（ADR-0078）只負責完整個人資料的備份與復原，不再是帶到手機的主要方式。
- 新增一張匿名資料表與兩個公開 Function。成本為每次建立一筆 D1 寫入；每次開啟兩次讀取（`/s/<shareId>` 頁的 metadata 與閱讀端預覽各一次），不新增 Cloudflare 產品。
- 分享連結可被任何持有者轉傳，到期前無法撤銷或更新；分享前明說。

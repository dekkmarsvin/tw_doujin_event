# ADR-0012：資料來源只留主辦官網與社團本人

- 狀態：已定案（2026-08-18）
- 延續：[ADR-0010：社團身分改用配發的流水號](./0010-circle-identity-is-an-allocated-serial.md)
- 相關契約：[社團目錄契約](../contracts/circle-catalog.md)、[資料匯入契約](../contracts/data-import.md)
- 相關流程：[社團資料更新](../runbooks/catalog-data-update.md)

## 脈絡

本站目前的資料有三個上游，其中兩個不是主辦官網：

| 來源 | 供應什麼 | 是否官網 |
|---|---|---|
| 社群維護的 FF47 Google 試算表 | 1,336 筆社團模板、5,137 個外部連結、336 筆販售資訊、全部搜尋 facet | ✗ |
| 公開縮圖索引試算表（Excel 以 `IMPORTRANGE` 查詢） | 262 張縮圖的 join key | ✗ |
| `f-2.com.tw` 三日攤位編號公佈 | 目前只當 `SourceLink.url` 的標示連結 | ✓ |

三個問題疊在一起：

1. **授權沒有依據。** 社群整理的試算表是別人的勞動成果，本站把它重新發布，沒有可以指向的授權。這是 [ADR-0011](./0011-ff47-is-not-a-public-launch.md) 閘控至今的第一個原因。
2. **縮圖讓讀者對第三方發出請求。** 262 張圖直連 `drive.google.com`，每位讀者的瀏覽器都會向 Google 揭露自己的 IP 與正在看哪一頁。社團自填縮圖已經因為同一個理由限制在允許清單內的主機（見[社團自助控制面契約](../contracts/circle-portal.md)的 Media Safety）；主線資料卻沒有受同一條規則約束。
3. **官網明明是配置權威，卻只被當成註腳。** `FF47_OFFICIAL_BOOTH_LIST_URLS` 目前只用來產生「查看原始來源」連結。真正決定誰在哪個攤位的，是那份社群試算表。

[ADR-0010](./0010-circle-identity-is-an-allocated-serial.md) 把社團身分從工作簿解耦時，已經預告了這一步：「這正是淘汰工作簿的前置條件：身分一旦不依賴工作簿，工作簿就可以逐步被社團自填的資料取代，而不會動到任何既有的收藏、行程與認領。」前置條件成立了，缺的是決定。

## 決策

**長期只保留兩類資料來源：活動主辦官網，與社團本人自填。**

- **主辦官網供應活動事實**：攤位配置、日期、社團名。`f-2.com.tw` 的三日攤位編號公佈從標示用連結升格為正式匯入來源，比照現有 `source:check` / `source:update` 的形狀——先看差異、確認後更新、產物進版本控制、驗證失敗一律 fail closed。
- **社團本人供應內容**：介紹、販售資訊、連結、縮圖、作品標籤。管道已經存在，就是 `/circle`。
- **所有非官網第三方來源逐步退場**，並且**不再新增任何第三方抓取來源**。

「逐步」是刻意的。工作簿目前供應的內容欄位沒有任何替代來源，一次移除會讓場刊只剩攤位號與社團名。退場順序是：先建立官網管線並把配置權威移過去，再逐項把內容欄位交給社團自填，最後移除工作簿。

## 後果

### 直接獲得

- **公開發布有了授權依據。** 主辦官網的活動事實與社團自己填的內容，都是本站可以指向來源的資料。這解開 [ADR-0011](./0011-ff47-is-not-a-public-launch.md) 兩個閘控前提中的一個。
- **`SourceContentType` 的 `catalog`（公開整理）在退場完成後不再有生產者。** 型別可以保留給歷史資料，但不再有新內容進來。
- **CSP 的 `img-src` 可以從 `https:` 收緊到允許清單。** 目前 `public/_headers` 對圖片開放整個 HTTPS，因為 Drive 圖床需要它。

### 必須處理的代價

- **場刊內容會先變薄再變厚。** 工作簿退場與社團自填補回之間有一段空窗；那段期間沒有縮圖的社團維持文字卡（既有行為已支援），但介紹與販售資訊會缺。這是真實的退步，不是可以靠實作迴避的。
- **社團自填的覆蓋率決定內容品質。** 從「有人幫全部 1,336 個社團整理好」變成「每個社團自己來」，覆蓋率是營運問題，不是工程問題。
- **官網解析是脆的。** `f-2.com.tw` 是 WordPress 頁面，版面改了解析就壞。因此驗證必須 fail closed：抓不到表格、列數異常少、HTTP 非 200 都要中止而不是發布半份資料。
- **官網與工作簿在並存期會衝突。** 同一個攤位兩邊名稱不一致時，比照 identity registry 的既有做法 fail closed 並輸出人工裁決報告，不自動採信任一方。

## 不在本 ADR 範圍

- 退場的完整時程，以及工作簿最終移除的時間點。
- 內容欄位交給社團自填的先後順序。
- 是否為其他活動（FF48、其他台灣同人展）另建官網 adapter，以及那些官網的資料形狀。
- 縮圖是否改為本站自行代管而非只依賴社團提供的 URL。

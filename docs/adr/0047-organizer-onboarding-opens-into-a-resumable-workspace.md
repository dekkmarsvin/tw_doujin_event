# ADR-0047：Organizer onboarding 先引導，完成基礎設定後開放為可續作工作區

- **狀態**：Accepted
- **日期**：2026-08-31
- **延續**：[ADR-0035](./0035-new-event-onboarding-is-data-driven.md) 的資料驅動 onboarding、[ADR-0038](./0038-authoring-moves-to-the-control-surface-local-stays-as-backup.md) 的 Web 控制面方向
- **相關文件**：[產品定義](../../PRODUCT.md)、[設計系統](../../DESIGN.md)、[主辦單位工作區契約](../contracts/organizer-workspace.md)

## 背景

Organizer 的主要使用者是低頻、可能第一次操作，而且會跨多次登入才完成一場活動的主辦人。現行工作區把「活動、場館與展區、攤位匯入、地圖、驗證與預覽、送審與發布」六步並列，任何時候都能自由切換；它適合知道下一步要做什麼的人，但第一次建立活動時，同時出現全部概念與控制會增加判斷負擔。

完整 Wizard 能降低第一次操作的負擔，卻不適合成為活動整個生命週期的唯一介面。主辦在匯入、地圖、驗證與送審之間會反覆修正；若每次都必須依序前進，既有資料的局部修正會變成繞路。

因此問題不是在「Wizard」與「自由工作區」之間二選一，而是何時需要引導、何時應解除線性限制，以及兩者如何維持為同一個工作區。

## 決策

### 1. 同一個 Organizer 工作區有兩個階段，不建立兩套永久介面

- **首次引導階段**採「引導式任務站」：一次呈現一個目前任務，以進度、前置條件與明確的下一步協助完成活動基本資料及場館設定。
- **持續維護階段**採「活動建置冊」：保留活動清單、目前工作頁與整體 readiness，允許在六個主要區段間自由切換。

兩個階段共用相同資料、表單、地圖編輯器、驗證結果與發布狀態；不得為 Wizard 複製另一套欄位、資料模型或儲存路徑。

### 2. 引導範圍只涵蓋開始後續工作的必要基礎

首次引導依序協助完成：

1. 活動名稱、識別碼與活動日；
2. 至少一個有效的場館空間與展區配置。

以上基礎完成後，預設轉入活動建置冊。攤位匯入、地圖、驗證、預覽與送審仍提供建議順序與 readiness，但不以 Wizard 強制線性操作。

步驟完成條件必須來自既有草稿解析與驗證規則，不能另外維護一套只供進度條使用、可能與實際可送審狀態漂移的判斷。

### 3. 引導可退出，工作區不因後續錯誤自動退回 Wizard

- 引導階段提供「儲存並離開」、「繼續上次進度」及「查看全部任務」。
- 只有技術上無法開始的前置缺口可以阻擋下一步；尚可提前準備的內容不因建議順序而隱藏。
- 一旦某候選活動進入活動建置冊，之後即使修改前段資料而產生新的驗證錯誤，也留在活動建置冊，以 readiness 與阻塞項引導修正，不自動把使用者送回 Wizard。
- 這個階段轉換必須逐候選活動保存，不能只存在單一瀏覽器頁籤的暫時狀態；具體欄位與遷移方式留給實作票決定。

### 4. 活動建置冊以「目前工作、整體狀態、下一步」為固定資訊架構

- 左側：可管理活動與活動狀態；切換活動時保留各自的工作脈絡。
- 中央：目前區段的主要工作頁；同一時間只讓一個主要任務取得最高視覺權重。
- readiness 區：完成度、阻塞項、最後儲存狀態與建議下一步。它是導覽，不取代正式 validation。
- 六個主要區段保持可直接到達；目前位置、完成、阻塞與未開始同時以文字、位置及圖形表達，不只靠顏色。

### 5. Organizer 沿用全站設計系統，不保留獨立深色主題

Organizer 與 Reader 在資訊架構與操作密度上保持視覺分離，但元件語彙仍以 [`DESIGN.md`](../../DESIGN.md) 為權威：暖紙底、柔白工作面、一像素結構線、深墨主操作、緊密字級與語意色彩。管理介面的差異來自任務結構與狀態呈現，不另建深色、金色或漸層的品牌分支。

### 6. 本 ADR 不改變領域能力與發布邊界

活動建立、匯入、地圖、驗證、預覽、送審、核准、權限與 publication fail-closed 行為維持[主辦單位工作區契約](../contracts/organizer-workspace.md)的現況。本 ADR 只決定後續介面如何引導與組織這些能力。

在實作合併前，現行介面仍是 shipped behavior；屆時應在同一批變更中更新 Organizer contract 的可驗收介面行為。

## 結果

- 第一次建立活動時，畫面只要求理解目前能完成的任務，不必預先理解匯入、地圖、審閱與發布的全部細節。
- 完成基礎設定後，主辦可以跨區段修正，不會被永久 Wizard 限制。
- 進度條、readiness 與正式 validation 必須共用同一組領域判斷，避免介面顯示完成但送審仍失敗。
- 實作需要加入逐候選活動保存的 onboarding 階段，以及可恢復的目前任務；這是流程狀態，不是新的活動發布狀態。
- 現有 Organizer 深色 CSS 不再是後續工作的設計權威；改版應回到 `DESIGN.md`，但不因本 ADR 立即修改任何 shipped UI。

## 驗收方向

- 新候選活動預設進入引導式任務站。
- 重新登入或切換回該活動時，可以繼續上次任務。
- 完成活動資料與場館設定後，預設進入可自由切換的活動建置冊。
- 使用者可以從引導階段查看全部任務，不被不必要地鎖在單一路徑。
- 已進入活動建置冊的候選不因後續 validation error 自動退回 Wizard。
- progress、readiness 與 validation 對同一缺口不會給出互相矛盾的狀態。
- 桌機最小寬度、身分、權限、版本衝突與發布邊界維持現有契約。

## 未決

- 「繼續上次進度」應以 URL、候選活動欄位或獨立的使用者偏好保存；實作必須滿足跨登入恢復，不能只依賴元件記憶體。
- readiness 的百分比是否需要顯示。若無法讓不同任務權重具有可理解語意，優先顯示「已完成區段／總區段」與具名阻塞項，不製造精確但無意義的數字。

# ADR-0005：匯入維持 P2，一般介面只保留安全匯出

- 狀態：已定案（2026-08-06）
- 相關契約：[收藏與走訪規劃契約](../contracts/planning.md#匯出與匯入分期)、[資料匯入契約](../contracts/data-import.md)

## 脈絡

實作進度一度跑到分期前面：一般介面已經出現 JSON／CSV 匯入匯出與衝突選項，但正式模組文件仍把匯入列為 P2。文件與產品互相矛盾，而矛盾本身比兩個選項中的任何一個都糟——沒有人知道哪一邊是真的。

兩個可行的收斂方向：
1. **接受提前實作**：把它標示為已完成的 P2 子項，補齊隱私、衝突與刪除政策。
2. **維持原分期**：暫時隱藏匯入入口，只保留可恢復性所需的安全匯出。

## 決策

**維持原分期。** 一般介面隱藏匯入入口，只保留復原用途的安全匯出（版本化 JSON 與 CSV v1）。匯入、衝突預覽與寫入 UI 保留在 P2。

理由：匯入是**破壞性寫入**。它需要身分比對規則、衝突預覽、可復原批次與明確的刪除政策才算完整；在這些沒定義完之前開放入口，等於讓使用者用自己的規劃資料去試錯。而匯出是純讀取，且因為 [ADR-0002](./0002-planning-data-stays-on-device.md) 沒有伺服器備份，它是資料復原的**唯一**邊界——所以匯出屬 P0，匯入屬 P2，這不是同一件事的兩半。

## 後果

- `PRODUCT.md`、`DESIGN.md` 與所有模組契約對匯入狀態必須一致：**未實作**。
- 匯出必須完整：schema version、群組、收藏、備註、行程、購買項目與預算，且 CSV 對可能被試算表解讀為公式的值安全轉義。
- [資料匯入契約](../contracts/data-import.md)保留完整設計，但開頭明寫「一個都還沒做」，避免被誤讀為現況。
- 解除這個分期需要同時交付：身分比對、預覽分類、確認流程、批次紀錄與可復原寫入。少任何一項都不算完成。

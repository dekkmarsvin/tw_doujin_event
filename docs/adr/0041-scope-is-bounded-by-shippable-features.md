# ADR-0041：交付範圍以可實現功能為界，邊緣契約降級為紀錄

- 狀態：已定案（2026-08-30）
- 延續：[ADR-0040](./0040-review-findings-are-bounded-by-the-ticket.md)（同一個判準，作用範圍由 review thread 擴大到 backlog 與契約文件）
- 相關 issue：[#85](https://github.com/dekkmarsvin/tw_doujin_event/issues/85)、[#104](https://github.com/dekkmarsvin/tw_doujin_event/issues/104)、[#117](https://github.com/dekkmarsvin/tw_doujin_event/issues/117)、[#118](https://github.com/dekkmarsvin/tw_doujin_event/issues/118)
- 相關契約：[搜尋、篩選與顯示設定契約](../contracts/search.md)

## 問題

[ADR-0040](./0040-review-findings-are-bounded-by-the-ticket.md) 在單一 PR 的尺度上解決了「修補面積隨輪次成長」的問題。但同一個漂移在**專案尺度**上仍然存在，而且 backlog 本身就是證據。

2026-08-30 的 open issue 全景：

| Issue | 是什麼 | 有沒有使用者看得到的行為 |
|---|---|---|
| #85 | 五個場館的 reference 編目 | 沒有。沒有任何活動選取這些場館 |
| #104 | 新活動 onboarding epic | 沒有。是維護者工序 |
| #117 | authoring 搬上 Pages（P2、已延後） | 沒有。且解除條件是「第二場活動實測證明有必要」 |
| #118 | GitHub PR／pin orchestration（已凍結） | 沒有。且自己寫明不發 token |
| #119 | production event selection 不硬編 FF47 | 沒有，但它是第二場活動的實際前置 |

**五張票，零張是產品功能。** 同一時間，`docs/contracts/search.md` 有三條標著 `未實作` 的使用者能力（多主題 AND／OR、排除主題、命中原因說明）從來沒有進過追蹤面。

commit 歷史指向同一件事。最近一批合併的訊息是 `Count quoted carriage-return source lines`、`Honor zero rowspans within row groups`、`Reject case-colliding booth codes`——都是主辦網頁 HTML 的極端輸入處理。它們各自正確，但它們回答的是「這份 HTML 有沒有可能長成這樣」，不是「使用者能不能完成任務」。

成因不是任何一次判斷失誤，是**兩種工作的成本訊號不對稱**：邊緣情況有明確的觸發器（一條 review finding、一個 schema 縫隙、一個想像得到的 malformed 輸入），功能沒有；邊緣情況可以立刻寫成驗收條件，功能要先決定產品行為。於是 backlog 自然往前者傾斜，而且每一步都說得出理由。

## 決策

### 1. 交付範圍的預設值是功能，不是完備性

一項工作要進入 backlog，必須先回答：**哪一條 [`PRODUCT.md`](../../PRODUCT.md) 的 Core User Task 因此變得可完成、或明顯更省力？**

答不出來的，不是禁止做，而是**不進入交付範圍**，改以 `wontfix` 或 `needs-triage` 記錄。這與 ADR-0040 決策 5 的姿態一致：「不做」是合法結果，但必須留下紀錄。

### 2. 邊緣契約的定義

以下四類統稱**邊緣契約**，預設不進入交付範圍：

- **極端值的格式檢查**：只有在輸入超出實務範圍時才會分歧的驗證（宣告像素上限、交錯／漸進式編碼、xref-stream、`\r` 引號跨行、大小寫碰撞的攤位代碼）。
- **刻意製造才會發生的意外**：需要有人主動並發執行、在兩次 rename 之間終止行程或以敵意輸入攻擊本機工具才會觸發的狀態。ADR-0040 決策 1 的威脅模型已排除，本 ADR 把同一條界線套用到新工作。
- **推測性的擴充**：為尚不存在的活動、場館或資料形狀預先建立資料或抽象。真實需求出現時再做，成本不會比較高。
- **無消費者的資料欄位**：沒有任何介面、審閱或發布行為會因為它的值而改變。#89 已是這個判準的先例。

### 3. 已實作的邊緣行為不回頭拆除

本 ADR **不**授權移除既有的驗證、清除或 fail-closed 邏輯。它們已經通過 gate、有測試、且移除本身就是一次有風險的變更——那正是本 ADR 想避免的成本形狀。

界線是**未來的工作**：不再新增這一類，不再讓它們排在功能前面。

### 4. 契約文件必須把「已延後」寫成已延後

`docs/contracts/` 描述現況。一條契約若是邊緣契約且未實作，不得留在契約正文裡當作待辦——必須標成 `邊緣契約（不排入）`，並寫明依據。契約落後或超前實作都是 bug，這條把「超前」也涵蓋進來。

### 5. 功能缺口要有票

`未實作` 出現在契約表格裡，卻沒有對應 issue，等於這個缺口沒有人在追。契約標成 `未實作` 的使用者能力必須開票，或在同一次修改中改標成 `邊緣契約（不排入）`。

## 後果

- #117 與 #118 以本 ADR 關閉。兩者都已自陳解除條件是「第二場真實活動跑完之後再看」——那是**重新評估的觸發器，不是待辦**，留著只會讓 backlog 看起來有五張票在動。#104 的 epic 內文仍保存它們的重啟條件。
- #85 從「編目五個場館」改為需求驅動：有活動確定用哪個場館，才建立該場館的 record。取代 `tests/event-url-state.test.mjs` 合成 fixture 的那條驗收條件一併移除——它是拿真實資料去驗證一條已有測試覆蓋的 codec 規則，屬決策 2 的推測性擴充。
- #119 保留。它不是功能，但它是第二場活動的實際前置，符合決策 1 的「明顯更省力」。
- `docs/contracts/search.md` 的三條 `未實作` 依決策 5 開票並實作。
- 代價明確：本專案會**接受更多在極端輸入下的未定義行為**。主辦網頁若送出本 importer 未涵蓋的形狀，結果是 build 失敗與人工處理，不是自動修復。這是刻意的取捨，不是疏漏。
- 訊號：若同一類極端輸入在**真實資料**上重複出現兩次，它就不再是邊緣，改依決策 1 評估。

## 不在本 ADR 範圍

- 不改變 [`docs/README.md`](../README.md) 的維護規則、triage 標籤語彙或 gate 組成。
- 不改變 ADR-0040 的威脅模型本身，只延用它。
- 不對 P2 分期重新定義。P2 仍是「明確被推遲的範圍，解除需要對應的 ADR」（[`CONTEXT.md`](../../CONTEXT.md)），與本 ADR 的「邊緣契約」是兩件事：P2 是有價值但延後，邊緣契約是價值未證實。

# ADR-0071：主辦在匯入預覽確認跨日同名社團

- 狀態：已定案（2026-09-27）
- 相關 issue：[#413](https://github.com/dekkmarsvin/tw_doujin_event/issues/413)
- 部分取代：[ADR-0044](./0044-an-accepted-circle-list-is-not-yet-catalogable.md) 對同名跨日 grouping 必須另附證據的限制；錄取名單不能單獨配號的規則不變。
- 延續：[ADR-0010](./0010-circle-identity-is-an-allocated-serial.md)、[ADR-0045](./0045-list-changes-are-declared-not-inferred.md)。

## 決策

維護者確認同場活動跨日出展沿用相同社團名稱。新活動的主辦匯入流程先按此規則整理跨日社團，在匯入預覽與已存名單列出各日、場地與攤位供主辦核對；確認匯入、送審與核准沿用原流程，不要求每場另外匯入錄取名單。

1. 分組只處理同一活動的完整名單。名稱使用 NFKC、首尾與連續空白整理、大小寫正規化作精確比對，不做相似字串推測。無內部編號的同名列出現在兩個以上活動日時，歸為同一社團，保留所有原始配置，包括同日多列、多攤、換位或跨場地。
2. 明確的主辦內部編號優先。同名列只要有任一內部編號，就只按相同編號連結；空白編號的列不推測歸屬。單日同名列不因名稱自動合併。主辦可用不同內部編號區分同名的不同社團。
3. 品書、認領與收藏仍掛在配發的 `c-xxxxxx`；名稱不是 ID。公開 evidence 仍由每個 `<day>:<booth>` 配置構成。主辦確認的同名分組寫為 `manual-organizer-evidence`，reference 使用核准的官方來源網址，不能假造 `organizer-stable-key`。
4. 官方錄取名單可以用來確認跨日關聯與各日攤數，仍須與正式攤位表連接；沒有攤位編號不能配號。主辦核准 snapshot 固定最終列與分組規則，不在發布時重新抓名單。
5. CREATE 新送審使用 `organizer-submission-snapshot/5` 固定此規則；既有 `/3` 核准快照的產物不重新解讀，AMEND `/4` 繼續使用原身分與明確更正宣告。匯入預覽、Reader 預覽與 `/5` 發布共用分組函式。

## 本輪資料更正邊界

維護者明確接受 PF45×RF14 在 #413 開工前做一次已發布身分整合，且本輪不保留舊 ID 網址、收藏或認領的相容路徑。以官方錄取列及逐日攤位表確認關聯後，保留每組較早的既有 ID，集中其 booth evidence；原 allocations 保留、序號不重用，其他活動不變。

這是對已發布身分與核准內容不變規則的一次授權例外，不新增一般 AMEND 合併操作，不放寬 generator 的衝突／exact coverage 檢查。具體資料差異與驗收留在 issue／PR；往後透過首次發布前的主辦預覽確認避免重複配號。

# ADR-0078：讀者可匯入自己的完整規劃備份

- 狀態：已定案（2026-10-03，#415）。
- 部分取代 [ADR-0005](./0005-import-stays-p2-export-only.md)：只針對讀者自己的 `circle-plan-json/1` 完整備份解除匯入分期；CSV 匯入與外部服務匯入仍維持 P2。
- 相關契約：[收藏與走訪規劃契約](../contracts/planning.md#匯出與匯入分期)、[資料匯入契約](../contracts/data-import.md)

## 脈絡

規劃資料只存在瀏覽器（[ADR-0002](./0002-planning-data-stays-on-device.md)），一般介面只有匯出；換瀏覽器、換裝置或清除資料後只能重建。#415 把「展前整理不白費」列為採用成長第三階段的成果。

2026-10-03 維護者在 #415 決定：把本場行程帶到自己的手機、分享給朋友，走同一條短網址＋QR Code 流程；JSON 只負責完整個人資料的備份與復原，不作為一般「帶到手機」的主要流程。本 ADR 只處理後者。

ADR-0005 要求解除分期時同時交付身分比對、預覽分類、確認流程、批次紀錄與可復原寫入。那份清單寫給外部服務匯入：來源不是使用者本人、記錄需要逐列比對，寫入分多步。讀者自己的完整備份不同：

- 內容由同一套 planning schema 產生，社團以既有 `circleId` 識別，沒有名稱比對或候選。
- 寫入是一次 `localStorage` 寫入，成功與失敗都是整份；沒有中途失敗後需要重試的逐列狀態。

## 決策

**開放讀者自己的完整 JSON 備份匯入，只在本機進行，使用者主動選檔。**

- 只接受 `circle-plan-json/1` 與目前 planning schema；單檔 10 MiB、20,000 筆上限。未知版本、破損結構或任何不合法項目整份拒絕並說明原因，不以略過項目當成功。
- 寫入前一律預覽：依活動列出收藏與行程的新增、內容不同筆數及各日行程筆數，並把「活動資料尚未載入」與「目前無法匹配」分開；分類只供判讀，不刪除任何項目。本站未公開的活動，其項目列入「目前無法匹配的規劃資料」逐筆管理。
- 預設合併並保留目前內容，可明確改採匯入值；重複匯入不產生重複項目。群組以 id 識別，同 id 不同內容時重新編號並更新引用。
- 完整取代是獨立的危險操作：列出全瀏覽器各活動會被取代的筆數、提供先匯出備份，並二次確認。
- 預覽與確認都以瀏覽器目前保存的資料為準（含其他分頁剛寫入的內容）；預覽後若已改變，重新計算並再次確認。儲存失敗時不宣稱成功，已保存的資料不變。瀏覽器保有無法讀取的舊資料時不開放匯入，避免覆寫受保護的原始資料。

批次紀錄不適用：沒有外部來源、沒有逐列寫入，整份寫入失敗即等於沒有寫入。身分比對以既有 `circleId` 與孤兒規則承接，catalog 找不到的社團照原記錄保留。

## 後果

- 「資料管理」的「完整備份」提供「匯出備份」與「從備份復原」。CSV 仍可匯出，但介面不稱其為完整多日備份，也不開放 CSV 匯入。行程面板不另設 JSON 入口；帶到手機與分享由短網址流程承接。
- `planning-transfer` 的 JSON 匯入路徑不再過濾未知社團；外部匯入、CSV 匯入與其批次紀錄要求維持 ADR-0005 與[資料匯入契約](../contracts/data-import.md)的 P2 設計。
- 匯入不經後端、不新增帳號或雲端同步；轉移是單次的，之後兩台裝置各自修改。

# ADR-0011：FF47 期間全站不公開

- 狀態：已定案（2026-08-18）
- 相關契約：[社團自助控制面契約](../contracts/circle-portal.md)、[資料傳輸與離線契約](../contracts/delivery-and-offline.md)
- 相關流程：[部署](../runbooks/deployment.md)

## 脈絡

站台原本朝 FF47 公開測試準入推進：地圖、搜尋、收藏、行程與社團自助控制面都已實作並通過完整 gate。閘控是後來加的，`docs/runbooks/deployment.md` 把它寫成「在來源授權確認前」的暫時措施，只列出 Zero Trust 的 Bypass 路徑表，沒有說這個「前」要等到什麼。

於是同一件事在兩份文件裡有兩種讀法。`README.md` 說公開閱讀路徑是純靜態的、由邊緣直送——技術上正確，Access 在邊緣層，確實不是 Worker——但新進者讀完會以為站台已經對外開放。

而閘控之所以還在，有兩個沒有解決的前提：

1. **資料來源的授權未確認。** 目前的社團內容權威是社群維護的 Google 試算表，媒體來自 Google Drive 圖床。把它們公開重新發布，本站沒有可以指向的授權依據。
2. **沒有使用條款與隱私告知。** 社團端已處理 email、login token、session、IP hash、認領、補充資料與稽核記錄，但保存期限與刪除規則尚未定案（見 issue #30）。

第二點還有一個時序問題：如果先邀請真實社團、之後才決定保存政策，implementation 會先形成不可逆的事實標準——資料已經在庫裡了，政策只能追認它。

## 決策

**FF47 期間全站維持 Cloudflare Access 閘控，含社團端。**

- Zero Trust **不保留任何 Bypass 路徑**。原本為了讓社團登入而放行的 `/circle`、`/api/auth/*`、`/api/claims/*`、`/api/circle/*` 與共用的 `/assets/*`、`/fonts/*` 一併移除。
- **不邀請任何真實社團**，因此 FF47 期間不收集任何真實個人資料。
- FF47 的資料與地圖留在 repo 內，作為已驗證的第一份活動範例；它不是公開發布目標。

這不是延期，是改變目標。本站的長期方向是開源的同人展地圖網站（見 [ADR-0012](./0012-first-party-sources-only.md)），FF47 是它的第一份驗證資料，不是它的發表場合。

## 後果

- **公開瀏覽在 `PRODUCT.md` 裡是設計目標，不是現行狀態。** 產品文件必須分開描述這兩者，否則會像在陳述一件沒有發生的事。
- **issue #30 從 launch blocker 降為「邀請真實社團前的 blocker」。** 它仍然開著、範圍不變；改變的只是它擋住的那道門什麼時候會被推開。研究用途例外維持關閉。
- **issue #29 的 preview portal 端到端驗收變成唯一的社團端操作環境。** 沒有 production 真實流量可以對照，preview 就是社團端行為的全部證據；它的價值因此上升，不是下降。
- **社團端功能繼續開發，但沒有真實使用者回饋。** 認領證據規則、審核流程與退出機制只能靠 preview 的 E2E 驗證，不會有人來踩出設計沒想到的路徑。這是這個決策確實付出的代價。
- **`README.md` 需要一句指路，不是一份複製的閘控說明。** 依 `docs/README.md` 的「一個契約只有一個家」，路徑細節只留在部署 runbook。
- **閘控狀態本身要能被驗證。** 移除 Bypass 後必須以未授權瀏覽器實測 `/`、`/circle` 與 `/api/auth/session` 全部落在 Access 登入頁；「應該關了」不是關了。

## 不在本 ADR 範圍

- 何時、以什麼條件重新開放公開瀏覽。那需要來源授權（[ADR-0012](./0012-first-party-sources-only.md) 的主線工作）與正式條款兩者都完成。
- 使用條款、隱私告知與資料保存期限的內容——見 issue #30，需要營運與專業審閱。
- 是否為未來的活動（FF48…）另行決定公開時程。

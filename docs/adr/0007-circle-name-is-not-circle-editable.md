# ADR-0007：社團名稱不可由社團自行編輯

- 狀態：已定案（2026-08-13）
- 來源研究：[Comike WebCatalog 社團自助編輯研究](../research/comike-webcatalog-circle-editing.md)
- 相關契約：[社團自助控制面契約](../contracts/circle-portal.md#可編輯範圍)

## 脈絡

本專案原本把社團名稱設為「**需審核後生效**」——比 Comiket 更寬鬆。實地檢視 Comiket 的社團編輯端後發現，它的社團名是**完全不可編輯**的，頁面明文標示某些欄位不能變更；社團只能修改「刊登用執筆者名」，其初值來自申請內容、可在此訂正。

回頭看本專案的資料模型，社團名稱同時是三樣東西：

1. **攤位比對鍵**——生成器用正規化名稱把 Excel 主資料列接到主辦當日攤位清單。
2. **縮圖索引 join key**。
3. 歷史上曾是 `circle.id` 雜湊輸入；此理由已由 [ADR-0010](./0010-circle-identity-is-an-allocated-serial.md) 消除。

改動它仍可能讓社團脫離自己的攤位或縮圖；allocated ID 已確保收藏不因改名失效，但沒有消除另外兩個 join 的風險。

## 決策

**社團名稱完全不可由社團編輯**，並移除原本的「名稱需審核」流程。

名稱錯誤由**管理者在上游試算表更正**，再重新生成場刊——那才是單一來源。

社團可編輯的是「筆名」（`pen`），對應 Comiket 的刊登用執筆者名。

## 後果

- 少了一條審核流程要維護，也少了一個「審核通過但資料炸掉」的失敗模式。
- 名稱訂正的延遲變長：要更新上游與 identity evidence registry，再重建場刊。`catalog:check` 會驗證固定 ID 與產物同步。
- 攤位、日期與 `SourceLink` 同樣永不開放，理由相同：它們是身分與定位的權威，不是展示內容。
- 同時採納的另外兩項調整（**儲存前刊登預覽**、**活動後可見性退出**）記在[社團自助控制面契約](../contracts/circle-portal.md)，不另開 ADR——它們是新增能力，不是推翻既有決策。

# ADR-0004：加入行程與設為下一站是兩個獨立動作

- 狀態：已定案（2026-08-06 實作完成）
- 相關契約：[收藏與走訪規劃契約](../contracts/planning.md#不變量)

## 脈絡

原本的 `addToVisitPlan()` 在當日還沒有下一站時，會把新加入的項目直接建立為 `next`。表面上是貼心的預設值，實際上讓「我把這個社團排進今天」和「我現在要去這一攤」變成同一個動作。

後果是使用者無法在不改變目前導航目標的情況下擴充行程：每加一個新社團，畫面上的「下一站」就可能被改掉。狀態模型一旦這樣糊在一起，後續所有依賴 `next` 的 UI（地圖箭頭、導航模式聚焦、行程浮條）都會建立在錯誤的語意上。

## 決策

- **加入行程一律建立 `planned`。**
- **只有「設為下一站」可以建立或轉移 `next`。**
- 移除或走訪目前的下一站後，**不自動指定替代下一站**。
- 收藏、加入行程、設為下一站與標為已走訪是四個獨立動作。加入收藏不得自動改變走訪順序。

## 後果

- 使用者第一次加入行程後看到的是「待前往」，不是「下一站」。這是刻意的：下一站是一個需要被明確宣告的意圖。
- 每日最多一筆 `next`；設定新的下一站時原下一站回到 `planned`，且不取消其收藏。
- 導航模式在沒有 `next` 時聚焦第一個未走訪項目，而不是自己指派一個。
- 測試必須覆蓋四種轉移：首次加入、已有下一站時再加入、明確設為下一站、移除或走訪下一站。

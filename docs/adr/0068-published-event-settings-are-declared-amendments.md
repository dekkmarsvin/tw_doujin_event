# ADR-0068：活動別稱是活動資料，已發布活動的設定以宣告更正

- 狀態：已定案（2026-09-23）。由 [#366](https://github.com/dekkmarsvin/tw_doujin_event/issues/366) 實作：決策 1 在第一個 PR，決策 2、3 在第二個 PR。
- 相關 issue：[#366](https://github.com/dekkmarsvin/tw_doujin_event/issues/366)、[#362](https://github.com/dekkmarsvin/tw_doujin_event/issues/362)、[#338](https://github.com/dekkmarsvin/tw_doujin_event/issues/338)
- 延續：[ADR-0045](./0045-list-changes-are-declared-not-inferred.md)（名單變動要宣告）、[ADR-0028](./0028-versioned-json-event-definitions.md)（活動定義版本化）、[ADR-0039](./0039-one-data-repo-for-events-and-references.md)（活動與 reference 同一個 data repo）、[ADR-0054](./0054-the-retention-choice-is-withdrawn-publish-or-delete.md)（保存期限選項撤回）

## 問題

已發布活動的設定沒有更正路徑。發布後更正只能表達退出、換手、移動、新增四種名單變動；修正候選的一般設定儲存一律回 409 `amendment_declaration_required`，產檔也要求草稿與活動資料都等於已發布的基準。活動改名或改期，唯一的辦法是直接改已發布位元組，也就是[主辦工作區契約](../contracts/organizer-workspace.md)所說的治理例外。

2026-09-23 的 SEO 稽核再加上一個缺口：讀者與主辦用來稱呼活動的名字（「FF47」「CH20 百合ONLY」）不在活動資料裡，搜尋引擎因此對不上讀者的查詢。稽核曾提出在主 repo 維護一份別稱對照表，維護者否決：**主 repo 不承接活動資料**。活動內容只由主辦工作區撰寫、經核准 snapshot 發布；缺的更正能力應該補在發布後更正，而不是另開一條繞過審核的路。

改期還有一個隱藏的後果：社團資料列的 `retention_expires_at` 是寫入時依活動結束時間算好、存在列上的，活動日期改變時不會跟著更新。

## 決策

### 1. 活動別稱是活動定義的選填欄位

- `event-definition/3` 新增 `aliases`：字串陣列，保留順序，**第一個是活動簡稱**。最多 5 個，每個 1–40 字，不得與活動名稱或彼此重複；比對時先做 NFKC 正規化並忽略大小寫。
- 沒有別稱時**不寫出這個鍵**，空陣列不是合法值。既有活動資料與每一份已核准 snapshot 重建出的位元組因此完全不變，已發布活動仍能通過發布後更正的基準比對。
- **不升 schema 版本。** 既有的 `/3` 資料全部仍然合法，新欄位只增加、不改變任何既有欄位的語意。ADR-0028 要求的是「不能靜默猜測」：格式錯誤的別稱在解析時一律拒絕。
- 由主辦在工作區建立與編輯候選活動時填寫，隨核准 snapshot 發布。主 repo 不維護別稱表或任何活動資料的對照檔。
- 別稱在介面上的呈現範圍另外決定（#362），本 ADR 只決定資料的歸屬與形狀。

### 2. 已發布活動的設定以宣告更正

- 修正候選除了名單宣告，另有**活動設定宣告**，兩者分開保存、分開比對。修正候選的草稿維持等於基準草稿；直接編輯草稿仍然回 409，行為不變。
- 可更正的欄位採**允許清單**：活動名稱、活動別稱、既有活動日的日期。活動日的數量與代號不變；新增或刪除活動日、場館與使用空間、展區、`areaMode`、`mapTemplate` 仍一律拒絕，因為它們會牽動攤位、地圖與 Circle ID，需要另外評估。
- 與基準相同的宣告值不保存。套上宣告後的草稿必須通過建立活動時的同一套驗證，所以日期與別稱的規則和首次發布一致。
- 送審的 snapshot 帶上設定宣告，核准時比對宣告與已保存的內容，不一致以 `snapshot_mismatch` 拒絕。
- 產檔以「基準草稿＋設定宣告」建出活動資料，並要求結果等於「基準活動資料＋宣告值」。日期範圍與活動結束時間依新日期、以首次發布同一個算法重算。除了允許清單內的欄位與 `dataUpdatedAt`，任何差異仍以 `snapshot_mismatch` 退件。

### 3. 活動發布後依結束時間重算保存期限

- 活動發布成功、發布狀態轉為 published 的同一個 batch 內，把該活動所有 `retention_choice = 'purge'` 資料列的 `retention_expires_at`，依新發布的 `eventEndsAt` 以原本的規則重算。
- 每次發布都重算。日期沒變時結果相同，可以重複執行。
- 不重新開放 ADR-0054 撤回的保存期限選項，也不動 `keep` 或未表態的資料列。

## 後果

- 已發布活動的改名、補別稱與改期都有工作區內的路徑，並留下核准紀錄，不再需要治理例外。
- 延期的活動，社團資料不會在新的活動結束時間之前被清除；提前時依同一規則提前。
- **接受的代價**：只能更正允許清單內的三類設定。日後要更正其他設定，需要新的 ADR 擴充清單，並處理它對攤位與地圖的影響。
- FF47 以舊流程發布，沒有主辦候選活動，無法建立修正候選。它已經結束，不另外處理；下一場在建立候選時直接填寫別稱。

## 不在本 ADR 範圍

- 別稱在介紹頁、首頁與地圖畫面的呈現（#362 與稽核決定 D9）。
- 新增或刪除活動日、場館、使用空間或展區的更正。
- 跨活動社團身分；ADR-0039 的暫緩不變。

# ADR-0079：分享的攤位清單以 URL fragment 承載白名單

- 狀態：已定案（2026-10-03，#415）。
- 相關：[ADR-0002](./0002-planning-data-stays-on-device.md)（規劃資料留在裝置）、[ADR-0078](./0078-own-planning-backups-can-be-imported.md)（自己的完整備份）
- 相關契約：[收藏與走訪規劃契約](../contracts/planning.md#分享我選的攤位)、[URL 檢視狀態契約](../contracts/url-state.md)

## 脈絡

讀者想把挑好的攤位推薦給朋友，但完整備份含私人備註、群組、購買項目與預算，不能拿來分享。#415 要求分享不連同私人欄位、不新增後端，接收者先看再決定是否加入自己的計畫。

## 決策

**分享清單是另一個小 schema，以 URL fragment 承載，不經本站後端。**

- 內容只有版本、活動 ID、所選社團 ID、必要的活動日與清單順序；由所選收藏／行程投影產生，不序列化 `PlanningDocument`。首版不提供附帶私人欄位的選項。
- 連結為 `/?event=<id>#share=<payload>`。fragment 不隨請求送到伺服器，因此不新增短網址、分享 API 或資料表。連結上限 8 KiB；超過時提供同一白名單格式的分享檔，不截掉項目、也不改用完整備份。
- 接收者開啟連結或分享檔時先看唯讀預覽，不寫入。社團名稱、攤位與退出狀態一律從最新公開資料解析；分享內容不能覆寫官方位置，未知 ID 不以同名社團代替。
- 接收者可另按「加入收藏」或選日期「加入行程」：只加入尚未存在的項目，行程新增為「待前往」並接在既有順序之後，不改動既有備註與順序。

## 後果

- 分享連結可被任何持有者轉傳；首版沒有撤銷、更新或同步，產生前明說。
- 解析在 fragment 上設長度與筆數上限並驗證 schema、活動與社團 ID 格式；格式錯誤的連結不會改動本機資料。
- 這是固定的社團清單，不是 #414 的動態題材條件，也不是持續同步。

# 兩輪 Comike WebCatalog 研究：產品文件更新建議

整理日期：2026-08-06

## 目的

本文件將以下實測紀錄收斂成 FF47 產品規格可採用的更新項目：

- [地圖功能紀錄](./comike-webcatalog-map-research.md)
- [資訊介面、收藏與資料串接紀錄](./comike-webcatalog-information-favorites-integration-research.md)
- [收藏持久性與清理驗證](./comike-webcatalog-information-favorites-integration-verification.md)

這不是要求複製 WebCatalog，而是把已驗證的成熟模式轉成符合本專案「攤位作戰桌」、SVG 向量地圖與 FF47 資料範圍的產品契約。

## 採納狀態

本文件列出的建議已於 2026-08-06 轉入下列具約束力的產品文件：

- [PRODUCT.md](../PRODUCT.md)：核心使用者任務、成功結果、產品邊界與產品原則。
- [DESIGN.md](../DESIGN.md)：搜尋、URL 狀態、三種社團資訊密度、收藏／規劃、來源顯示與顯示設定。
- [活動地圖模組設計](./event-map-design.md)：renderer 邊界、一般使用者流程、URL 契約與跨介面驗收。
- [收藏與走訪規劃模組設計](./favorites-and-visit-planning-design.md)：領域模型、生命週期、同步、匯出與分期。
- [社團資料來源與匯入模組設計](./circle-data-sources-and-import-design.md)：資料權威、身分比對、來源顯示、預覽匯入與 CSV v1。

本文件保留為研究到決策的追溯紀錄；後續實作與驗收以上述產品文件為準。

## 決策摘要

現有 `PRODUCT.md` 與 `DESIGN.md` 已確立高密度探索、收藏、路線及地圖雙向定位，但仍需要補足：

1. 同一份社團資料在列表、詳情與地圖側欄的資訊密度規則。
2. 搜尋、日期、場館／區域與選取攤位的可分享 URL 狀態。
3. 收藏不是布林值，而是有群組、Memo 與生命週期的規劃記錄。
4. 外部社群、作品與通販資料必須顯示來源，且不得取代本地社團身分。
5. 匯入與同步必須先預覽匹配結果，再由使用者確認寫入。

## 一、建議更新 `PRODUCT.md`

### P-01：加入核心使用者任務

建議在 `Users` 或 `Product Purpose` 後新增：

1. **探索作品**：依社團、作者、作品名與題材搜尋，快速比較社團內容。
2. **定位攤位**：依社團名或攤位代碼直接定位，並在內容與地圖之間往返。
3. **建立逛攤計畫**：收藏社團、分組、寫 Memo、安排下一站與順序。
4. **集中理解資料**：在本產品內辨識社團核心資料及外部作品、社群與通販來源，不必靠多個分頁自行拼接。

### P-02：加入產品成功結果

建議將成功條件具體化：

- 使用者能從搜尋結果在一次操作內開啟對應攤位位置。
- 分享或重新開啟網址時，能恢復活動日、區域與選取社團。
- 同一收藏狀態會同步出現在社團列表、詳情、地圖與規劃清單。
- 使用者能辨識每一筆外部內容的來源平台與原始連結。
- 匯入資料不會未經預覽就覆寫既有收藏或 Memo。

### P-03：加入產品原則

建議新增三條：

6. **一份資料，多種密度**：列表負責比較、詳情負責完整閱讀、地圖側欄負責位置決策；三者共享同一社團記錄。
7. **規劃資料屬於使用者**：收藏、群組、Memo 與路線必須可回顧、可修改，並預留匯出能力。
8. **來源透明勝過內容堆疊**：外部社群、作品與通販內容必須標示來源，不將無法追溯的縮圖混入社團資料。

### 產品邊界

建議明確排除：

- 不採用 WebCatalog 的使用倒數、付費牆或 Bronze／Gold 分級。
- 不因參考 WebCatalog 而改用 Leaflet 圖磚；維持本專案 SVG slot 直接互動。
- 第一階段不做背景自動同步；外部資料匯入必須是顯式、可預覽的使用者動作。
- 不照搬 18 個只有顏色的分類；FF47 應使用具名稱的規劃群組，顏色僅為輔助提示。

## 二、建議更新 `DESIGN.md`

### D-01：搜尋分成探索與定位

在 `Inputs / Fields` 增加：

- **探索搜尋**：搜尋社團名、作者、作品名與標籤，回傳可比較的結果清單。
- **地圖定位搜尋**：搜尋社團名或攤位代碼，直接移動地圖、選取 slot 並開啟詳情。
- 目前搜尋範圍、條件與結果數必須可見；大量結果使用分頁或增量載入。
- 空結果需保留查詢文字並提供清除或調整條件的下一步。

### D-02：URL 與導覽狀態

在 `Navigation` 增加：

```text
mapView = event + day + area + selectedCircle + selectedBooth + query
```

- 日期、場館／區域、選取社團及搜尋文字使用 URL 查詢參數保存。
- 重新整理、瀏覽器返回與分享網址都必須恢復相同的可見選取狀態。
- URL 不必保存短暫 hover、開關動畫或尚未套用的篩選草稿。

### D-03：社團資訊密度

建議新增 `Circle Information Surfaces`：

- **列表卡片**：主視覺、社團名、攤位代碼、題材、收藏／規劃狀態。
- **完整詳情**：加入作者、作品、說明、外部來源與通販資訊。
- **地圖側欄**：保留社團名、攤位、題材、主打作品與規劃動作；不複製完整長頁。
- 三個介面共享欄位順序、來源名稱及收藏元件，不能各自建立不同語意。
- 無資料欄位直接省略，不用大型空狀態填補。

### D-04：收藏與規劃

建議新增 `Favorites / Planning`：

```text
FavoriteRecord = circleId + groupId? + memo? + createdAt + updatedAt
FavoriteGroup = id + label + color + sortOrder
VisitPlanEntry = circleId + status + routeOrder?
```

- `FavoriteRecord` 的存在代表已收藏，不另保存容易不同步的 `isFavorite`。
- 群組必須有文字名稱；顏色不能是唯一辨識方式。
- Memo、群組與收藏狀態在列表、詳情、地圖及收藏頁同步。
- 下一站及路線順序屬 `VisitPlanEntry`，不要塞進收藏顏色。
- 移除收藏會刪除其群組與 Memo；有 Memo 時至少提供 Undo，或在不可復原時要求確認。
- 愛心適合立即切換；較高成本的路線重排與批次刪除才需要明確提交。

### D-05：來源與外部內容

建議新增 `Source-aware Content`：

- 外部內容卡片必須顯示平台名稱或圖示、內容類型與原始連結。
- 本地 `CircleRecord` 是社團／攤位身分來源；外部記錄只能附加，不得以相似名稱覆寫本地身分。
- 若內容是抓取或同步所得，需顯示最後更新時間及失敗／過期狀態。
- 外部連結開啟前應能看出目的地；禁止只有無標籤圖片。

### L-01：顯示設定

建議新增 `Display Settings`：

- 提供「緊密掃圖／資訊列表」兩種密度，不照搬 Web Cut／冊子 Cut 名稱。
- 允許調整每個社團顯示的作品圖片數，例如 0、1、3。
- 篩選至少包含活動日、題材／類型、區域與收藏／規劃狀態。
- 排序至少包含攤位順、社團名與最近更新；收藏頁另提供規劃順序。
- 複雜設定使用側欄及「套用／取消」；簡單排序可即時生效。
- 目前設定以文字摘要顯示，避免使用者忘記正在套用的篩選。

## 三、建議更新 `docs/event-map-design.md`

### M-01：一般使用者地圖流程

在管理流程之前新增：

1. 選擇活動日與區域；多館活動才顯示會場總覽。
2. 拖曳或縮放地圖，必要時以迷你圖確認目前範圍。
3. 依攤位代碼或社團名搜尋並定位。
4. 選取 slot，地圖高亮並開啟社團詳情。
5. 收藏、加入規劃或設為下一站；狀態立即同步到所有介面。

### M-02：擴充 `EventMapRenderer` interface

建議讓 renderer 接收穩定資料，而非自行取得社團或收藏：

```text
layout
slotStates[boothCode]
selectedBoothCode?
favoriteGroups[circleId]?
visitPlan[circleId]?
onSlotSelect(boothCode)
```

- renderer 只表達狀態與回報選取，不負責寫收藏或改 URL。
- 頁面 controller 負責把 URL、社團記錄、收藏與 renderer 串起來。
- 迷你圖若實作，使用相同 layout 的簡化投影，不另維護第二份座標資料。

### 地圖驗收條件

建議追加：

- 以含日期、區域及社團 ID 的網址開啟時，對應攤位被選取並顯示詳情。
- 從社團列表按「查看地圖」後，不需再搜尋即可看到對應 slot。
- 從地圖選取攤位後，詳情使用與社團頁相同的核心資料及收藏狀態。
- 使用滑鼠、觸控與鍵盤皆能選取攤位；縮放後仍可回到完整場館範圍。
- 收藏群組改變後，地圖、列表與詳情不需重新整理便同步更新。
- 來源資料缺少或載入失敗時，地圖仍能顯示攤位，不以外部資料失敗阻斷定位。

## 四、建議新增兩份模組文件

### `docs/favorites-and-visit-planning-design.md`

應定義：

- `FavoriteRecord`、`FavoriteGroup`、`VisitPlanEntry` 的資料模型與責任邊界。
- 加入、編輯群組、寫 Memo、移除、Undo、排序及跨介面同步。
- 同攤位多社團、社團取消參展及活動版本變更時的處理。
- 使用者資料的匯出與刪除語意。

### `docs/circle-data-sources-and-import-design.md`

應定義：

- 本地社團 ID、活動配置與外部 provider ID 的對應方式。
- `SourceLink`、`ExternalContent` 與同步狀態。
- CSV schema、版本、欄位驗證與最大檔案限制。
- 匯入預覽：已匹配、未匹配、衝突、重複、將新增、將更新。
- 寫入前確認、部分失敗摘要、重試及匯入紀錄。
- pixiv 或其他 OAuth 串接必須獨立授權，不因一般登入而自動啟用。

## 五、建議優先順序

### P0：現在寫入產品契約

- 一份社團資料、多種資訊密度。
- 探索搜尋與地圖定位搜尋。
- URL 深連結與狀態恢復。
- 收藏群組、Memo 與跨介面同步。
- 來源標示及本地社團身分優先。
- 地圖與詳情雙向同步驗收條件。

### P1：地圖與高密度瀏覽完善

- 地圖拖曳、縮放、重設及迷你圖。
- 顯示密度、圖片數、篩選與排序。
- 收藏清單與規劃順序。
- 移除含 Memo 收藏的 Undo。

### P2：資料可攜與外部串接

- CSV 匯入／匯出。
- 外部收藏匹配與衝突預覽。
- pixiv 或其他平台雙向串接。
- 列印、企業／Cosplay 等非 FF47 核心入口。

## 六、不應照搬的 WebCatalog 行為

- 免費會員 3 分鐘瀏覽、5 分鐘等待。
- 付費方案阻擋核心地圖與收藏。
- 9／18 個只有顏色、沒有名稱的收藏分類。
- Leaflet 圖磚與圖片式攤位底圖。
- 移除收藏時無法預先理解 Memo 也會被刪除。
- 在沒有本地 ID 匹配與預覽的情況下直接把外部收藏寫入。

## 七、完成判準

產品文件更新完成時，應能從文件直接回答：

1. 使用者如何從作品找到攤位，再回到作品？
2. 哪些地圖狀態可分享並在重新整理後恢復？
3. 收藏、群組、Memo、下一站與路線各由哪個模型負責？
4. 同一社團在列表、詳情與地圖側欄各顯示哪些欄位？
5. 外部作品或通販內容如何標示來源及綁定本地社團？
6. CSV／外部收藏匯入如何預覽、處理衝突並由使用者確認？
7. 哪些功能屬第一階段，哪些明確延後？

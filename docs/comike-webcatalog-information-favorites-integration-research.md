# Comike WebCatalog 資訊介面、收藏與資料串接紀錄

- 紀錄日期：2026-08-06
- 目標網站：<https://webcatalog.circle.ms/>
- 測試身分：已登入、未訂閱的免費會員
- 研究範圍：資訊顯示介面、收藏流程、資料來源與外部串接

> 本文件記錄第二次實際操作結果，補充 [地圖功能紀錄](./comike-webcatalog-map-research.md)。文件不保存登入帳號或密碼。

## 研究摘要

WebCatalog 將同一批社團資料分成三種閱讀密度：社團列表負責快速掃圖、社團詳情負責完整閱讀、地圖側欄負責保留位置脈絡。收藏不是單一布林值，而是由「是否收藏、顏色分類、個人 Memo」組成；收藏清單再利用顏色、活動日、類型及場館作管理。資料呈現以 Circle.ms 社團資料為核心，向外連結作者社群、作品平台與通販平台；收藏資料另外支援 pixiv 雙向同步及 CSV 可攜式交換。

## 一、資訊顯示介面

### 1. 全站資訊骨架

- 第一列固定包含品牌、搜尋類型、關鍵字、搜尋按鈕、會員使用倒數、收藏捷徑、帳號與舊版入口。
- 第二列固定包含會場地圖、社團列表、收藏、企業攤位、Cosplay 與列印。
- 搜尋類型可在社團與企業間切換；社團搜尋可指定社團名、執筆者名及頒布物。
- 免費會員倒數持續顯示在全站外殼，不因切換列表、詳情或收藏頁而消失。

### 2. 社團列表

- 頁面使用高密度圖片網格，首要內容是社團 Web Cut 及作品／告知圖片，不先堆疊文字卡片。
- 社團卡片左上有收藏愛心，已收藏時以對應分類色填滿。
- 圖片下方保留社團名或作品名；同一社團可以連續顯示多張作品／告知圖片。
- 頂端使用小型狀態標籤顯示目前 Cut 類型、顯示模式與篩選狀態。

### 3. 顯示設定

社團列表的右側設定面板可調整：

- Cut 類型：Web Cut、冊子 Cut、影片 Cut。
- 顯示模式：Web Catalog、冊子 Catalog、社團詳情。
- 告知圖片／書店圖片／書籍圖片顯示數：0、1、2、3。
- 活動日：第 1 日、第 2 日。
- 類型：依活動實際ジャンル提供完整多選清單。
- 場館：東 1–3、東 7、西 1–2、南 1–2。
- 排序：新到順、配置順。

面板以「取消」與「套用並關閉」區分放棄及提交，避免篩選選擇立即造成大量版面跳動。

### 4. 社團詳情

- 首屏採左右兩欄：左側是主要 Cut；右側是社團名、收藏、分類選單、配置位置、MAP 連結及ジャンル。
- 次要欄位接續顯示 Email、作者、追加資訊與社團留言；沒有資料時保持空白，不以大型空狀態搶走注意力。
- MAP 連結包含活動日、場館與社團 ID，能返回對應地圖位置。
- 地圖點選攤位後使用同一組資訊內容作為右側詳情面板，因此列表、詳情與地圖沒有重新設計不同的社團資料結構。

### 5. 圖片與內容密度

- 使用者可以自行決定作品／告知圖片數量，將同一頁切換成快速掃圖或較完整的作品瀏覽。
- Cut、社團資料、作品圖片及外部平台內容有明確分區，不混成單一無來源瀑布流。
- 列表重視視覺比較，詳情重視欄位閱讀，地圖側欄則縮短為位置判斷所需資訊。

## 二、收藏流程

### 1. 加入與移除

- 社團列表、社團詳情及地圖詳情皆提供愛心入口。
- 點擊空心愛心會立即收藏；按鈕變為實心並套用目前分類色，不另外要求確認。
- 再次點擊實心愛心即可移除。
- 加入後收藏狀態會同步出現在收藏頁與其他社團顯示介面。

### 2. 顏色分類與 Memo

- 愛心旁的「＋」開啟收藏編輯浮層。
- 預設提供 9 種顏色，亦可切換 18 色。
- 顏色不是獨立標籤，而是直接改變收藏愛心的視覺狀態。
- 浮層提供自由文字 Memo 欄位，供使用者記錄購買、優先度或行程資訊。
- 浮層只有「關閉」操作，顏色在選取後立即反映；Memo 的跨頁持久性另在本次清理步驟驗證。

### 3. 收藏清單

- 收藏頁先切換「社團／企業」，再管理各自的收藏項目。
- 左側欄以收藏顏色作群組索引，每個色組旁有編輯入口。
- 內容區以圖片卡片呈現，卡片左上保留實心愛心及分類色。
- 篩選包含活動日、ジャンル及場館。
- 排序包含登錄順升／降、新到順、配置順及ジャンル順。
- 頁面將收藏管理、篩選與外部串接集中在「顯示設定」側欄，主內容仍維持高密度掃圖。

## 三、資料來源與串接

### 1. 社團核心資料

社團詳情可見的核心資料包含：

- Circle.ms 社團頁面；
- 社團名稱、作者、Email、留言；
- 活動日、攤位代碼、場館及ジャンル；
- Web Cut、冊子 Cut、影片 Cut；
- 告知圖片、書店圖片及書籍圖片。

Circle.ms 是頁面內的主記錄，其他來源以外部連結或內容群組附加，不取代主記錄的攤位身分。

### 2. 作者與社群來源

本次社團詳情實際出現：

- X；
- pixiv 個人頁；
- niconico 使用者頁；
- CLIP STUDIO PROFILE；
- Circle.ms Portal 社團頁。

這些來源以圖示排列在「追加情報」，使用者可以從場刊資料轉往作者持續經營的平台。

### 3. 通販與作品來源

- 詳情設有「通販・電子書籍取扱サイト」區段。
- 本次實見 Melonbooks 社團頁及商品頁。
- 作品內容依來源分組，例如 niconico 與 pixiv 各自列出對應作品連結。
- 來源平台名稱與內容分組並存，使用者能辨識連結去向，不只是看見無標示縮圖。

### 4. pixiv 收藏同步

收藏頁的「外部連携」提供雙向操作：

- 從 pixiv 匯入：依 pixiv 的收藏資訊，將對應社團加入 WebCatalog 收藏。
- 匯出到 pixiv：將 WebCatalog 的收藏社團登錄到 pixiv。
- 免費會員可以看見功能說明；實際執行會出現需要 Gold 方案的提示。

### 5. CSV 匯入與匯出

- 可讀取 Comike WebCatalog 收藏 CSV。
- 匯入支援檔案選擇或拖放。
- 畫面標示格式為 CSV、單檔上限 30MB。
- 可將目前收藏輸出成 CSV 檔。
- CSV 功能提供跨工作階段、跨工具或人工備份所需的可攜邊界。

### 6. 方案限制

- 方案比較將「外部服務連携」標示為 Bronze 不可用、Gold 可用。
- pixiv 同步實際觸發 Gold 購買提示。
- 收藏本身在 Bronze 可限制使用，仍受「使用 3 分鐘、等待 5 分鐘」規則影響。

## 四、介面狀態模型

從實際操作可整理出以下狀態：

```text
display = cutType + displayMode + imageCount + day + genre + hall + sort
favorite = isFavorite + colorId + memo
circle = identity + placement + profile + media[] + socialLinks[] + storeLinks[]
integration = pixivImport | pixivExport | csvImport | csvExport
```

值得注意的是，顯示偏好、收藏規劃與社團來源資料被分成三組，不使用同一個巨大設定面板混合管理。

## 五、可直接轉入 FF47 設計文件的模式

- 列表、詳情、地圖側欄共用一份社團資料結構，但依任務改變資訊密度。
- 顯示設定允許使用者選擇「掃圖」或「讀資料」，而不是由產品固定單一卡片密度。
- 收藏資料應至少包含是否收藏、顏色／群組與 Memo，而非只有 `boolean`。
- 收藏色組應同時出現在地圖攤位、列表卡片、詳情按鈕與收藏清單。
- 外部來源應保存來源類型及原始 URL，畫面需顯示平台身分。
- 匯入的外部收藏應先匹配本地社團 ID；無法匹配的資料要列入可檢查結果，不能靜默丟棄。
- CSV 應作為顯式匯入／匯出邊界，不直接覆寫使用者現有收藏；設計需預留預覽、衝突處理及結果摘要。

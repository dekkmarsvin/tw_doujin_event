# 日本同人／コミケ周邊服務功能盤點

- 紀錄日期：2026-08-14
- 調查方式：**公開網路檢索，未實地操作**
- 目的：盤點外部服務有哪些功能可能值得吸納，作為後續 ADR 的輸入

> 這份文件與 `comike-webcatalog-*.md` 三份**不同等級**。那三份是登入後逐項操作確認的實地檢視；本文是搜尋結果的二手整理，**沒有任何一項經過操作驗證**。引用時請照條目標註的可信度處理。

## 先讀：兩個調查限制

**一、無法實地操作。** 本次執行環境的網路出口只放行搜尋，`webcatalog.circle.ms`、`ja.wikipedia.org`、應用商店頁面等一律被擋，因此所有描述都來自搜尋引擎回傳的頁面摘要。條目標記三級可信度：

- `多來源一致` — 兩個以上獨立來源描述相同功能
- `單一來源` — 只有一個來源，且未經操作確認
- `未查證` — 只知道服務存在，功能描述不可靠

**二、「Spotgram」查無此服務。** 檢索過 `Spotgram`、`スポットグラム`、`spotgram.jp コミケ`、`Spotgram 攤位 場刊 同人`、`spotgram doujin event map app` 等組合，命中的都是不相干對象：`SPOTT 株式会社`的 Instagram 代營運服務、`豊田スポットグラム`這類地方觀光帳號。直接連線 `spotgram.jp` 與 `spotgram.net` 被本環境出口政策擋下，無法確認網域是否存在。

**在拿到正確網址或畫面截圖之前，本文不對 Spotgram 做任何功能描述。** 依 PRODUCT.md 的證據規則，猜測出來的功能清單會變成日後被反覆引用的假證據，代價高於留白。可能情況：名稱記錯、是極新或極小眾的服務、或是非日文圈的服務。

## 逐項功能紀錄

### コミケ Web カタログ：本次補到的新資訊

三份實地紀錄已涵蓋地圖、資訊架構與社團編輯。本次額外查到的是**資料出入口**：

- 收藏可**匯出成 CSV**，也可**匯入 DVD-ROM 版場刊產生的 CSV**，雙向互通。輸出編碼固定 UTF-8。
- **新規匯出是 Gold 會員限定功能**；匯入不限。
- 列印功能可依「參加日」「收藏顏色」等條件篩選後產生**列印用 PDF**。
- 收藏為 9 色分類 + 備註（與既有紀錄一致）。
- 社團端可隨時增修**頒布物資訊**，即時反映到一般參加者頁面。

可信度：多來源一致（`docs.circle.ms` 官方使用指南 + 第三方教學）。

### CircleMap：把地圖變成可帶走的紙本

功能重點：

- 把攤位格與**社團切圖用線連起來**，產生一張「哪一格是誰」一目了然的地圖。
- 社團標籤與地圖元素**可自由拖曳排版**，避開連線互相打結。
- 成品**存成圖片**，可列印或直接放在手機裡。
- 可從 Web カタログ／カタロム 的檢查清單**匯入**，形成「網頁上勾選 → App 產圖」的流程。
- 匯出走 Email 或 Dropbox。

這是整份盤點中最值得注意的一項：它的存在本身說明**官方地圖在現場不夠用**，使用者需要一份自己排版過、離線可用、可列印的成品。

可信度：多來源一致（作者官網 + 個人部落格評測 + App Store）。

### CircleCheck / CiRCLES / CiCl：離線與現場狀態

三個 App 的共同點是**事前把資料下載下來**，因為展場網路不可靠。

CiRCLES 另外有兩個現場導向的狀態：

- **訪問モード**：標記「這個社團我去過了」。
- **宝物リスト**：登錄頒布物／戰利品清單。

限制：CiRCLES 需要 Web カタログ **Gold 會員**才能使用。

可信度：多來源一致（App Store 說明 + 第三方介紹）。

### カタログマネージャー（仮）：多人清單合併

輸入是**カタロム 或 Web カタログ 輸出的 CSV 檢查清單**，功能是把多份清單**統合並集計**。使用情境是多人分頭跑攤、代購與共同購入——誰買哪一攤、有沒有重複、總共幾攤。

同一需求在民間也用 Notion 自建：把社團清單建成資料庫，登錄想買的品項與預算，當天照清單勾選。

可信度：多來源一致（作者站 + note 教學文）。

### 社群關係發現：從追蹤名單反查參展

`サークルチェックサイト`、`Circlesearch`、`CircleFinder` 解的是同一件事：**你追蹤的作者這次有沒有出攤、在哪一格**。做法是拿 X 的追蹤／被追蹤名單去比對參展社團清單。

這條路徑與關鍵字搜尋互補：使用者常常記得作者的帳號，卻不記得社團名。

可信度：多來源一致（多篇第三方介紹 + 現存服務帳號）。

### お品書き：頒布物清單是一種正式格式

「お品書き」在日本同人圈是既定格式，內容固定包含：活動名與日期、社團名與攤位號、每項頒布物的**標題、價格、新刊／既刊、CP、成人向標示、縮圖**。

有專門的產生器（お品書きメーカー 最多 5 品項、免註冊、手機可完成）與大量 Canva 模板。

重點不是「有工具可以做圖」，而是**頒布物本身有結構**：品名 + 價格 + 新刊/既刊 + 分級 + 圖。目前這些資訊在多數場刊裡是一段自由文字或一張圖。

可信度：多來源一致。

### pictSQUARE / pictSPACE：線上即賣會

pictSQUARE 是虛擬會場（單場最多 100 社團、頭像走動、可分區擴充），pictSPACE 是配套的同人通販服務，負責場內結帳、匿名配送。社團的「お品書き」在會場中點擊攤位時展開。

與本專案的關係只在**外部連結**層面：社團的通販頁是可被指向的來源，不是本專案要自建的能力。

可信度：多來源一致。

### 活動行事曆：ケットコム、Circle.ms

跨主辦的同人活動日曆，依日期與地區整理，**主辦方可透過登錄表單自行提報活動資訊**。這是「多活動」在日本圈的既有解法：場刊歸場刊，行事曆歸行事曆，兩者分開。

可信度：多來源一致。

### 台灣對照組

- **台灣同人通**（台灣同人誌中心）：活動依類型／地區篩選、時間排序、標記追蹤；作品瀏覽；登入後有筆記本；私訊；BOOKY 作品販售。定位是**社群 + 活動資訊平台**，不是場館地圖工具。
- **Popworld 電子場刊**：把博物館用的智慧導覽平台外掛到同人場，附帶電子集章、AR 互動、實境解謎。定位是**主辦方採購的活動加值方案**。

兩者都沒有踩在「高密度攤位地圖 + 個人行程規劃」這一格，這仍是本專案的空位。

可信度：台灣同人通 多來源一致；Popworld 單一來源。

## 可吸納候選

**以下都不是決策。** 每一項要落地都需要對應的 ADR 與契約修改；標示「衝突」的欄位是已知代價，不是否決。

### A 類：與現行決策相容，缺口明確

| # | 功能 | 來源 | 本專案現況 | 備註 |
|---|---|---|---|---|
| A1 | **收藏／行程的列印輸出** | Web カタログ 列印 PDF、CircleMap 出圖 | 無 | 純前端 print stylesheet，不動傳輸邊界。官方把它鎖在 Gold 後面，本專案沒有付費牆，可全部開放 |
| A2 | **標註過的地圖匯出成圖片** | CircleMap 核心價值 | 有向量地圖，無匯出 | 已經是 SVG，匯出 SVG／PNG 的邊際成本低。解的是「展場沒訊號、手機沒電」 |
| A3 | **頒布物結構化** | お品書き 格式、Web カタログ 頒布物登錄 | `saleInfo` 是 2000 字自由文字（`app/circle-overrides.ts`） | 拆成品名／價格／新刊既刊／分級後，`VisitPlanEntry.purchaseMemo` 可從自由文字變成勾選品項，`budget` 能自動加總。同時讓頒布物可被搜尋 |
| A4 | **依攤位座標建議走訪順序** | 民間 Notion 巡迴路線、CircleMap 排版 | `routeOrder` 存在但全靠手動 | 外部工具都做不到這件事，因為它們只有圖片地圖。本專案有 slot 座標，是**結構性優勢**而非模仿 |
| A5 | **現場模式：單手標記已走訪** | CiRCLES 訪問モード | `status = "visited"` 已有，但操作為一般密度 | 現場單手、戴手套、人擠人。屬 DESIGN.md 層級的調整 |
| A6 | **多活動與活動行事曆** | ケットコム、Circle.ms、台灣同人通 | 資料模型已 `eventId` 化，實際只有 FF47 | PRODUCT.md 已宣告要延伸到其他活動，這是把宣告變成介面 |
| A7 | **通販連結明確露出** | pictSPACE、BOOTH | `CircleExternalLink` 已有 `store` kind | 只需在詳情與行程列出「這攤可線上購買」。維持連結出去，不碰交易 |

### B 類：需要新 ADR 才能動

| # | 功能 | 來源 | 衝突 |
|---|---|---|---|
| B1 | **多人清單合併（共同購入）** | カタログマネージャー | 匯入整體是 P2（[ADR-0005](../adr/0005-import-stays-p2-export-only.md)）。可相容做法是「匯出 CSV → 他人匯入合併」，不需要伺服器，因此不牴觸 [ADR-0002](../adr/0002-planning-data-stays-on-device.md)；但要先界定「規劃資料合併」是否算 ADR-0005 所推遲的匯入 |
| B2 | **從社群追蹤名單反查參展** | Circlesearch、CircleFinder | 需要 X／pixiv 授權與伺服器端比對，同時牴觸 [ADR-0008](../adr/0008-static-public-reading-path.md) 的純靜態閱讀路徑與[資料匯入契約](../contracts/data-import.md)的 P2 分期。代價高，但這是唯一能解「記得帳號、不記得社團名」的路徑 |
| B3 | **追蹤社團的更新通知** | Web カタログ 通知 | 需要伺服器保存訂閱關係，牴觸 ADR-0002 與 ADR-0008。「讓伺服器知道誰收藏了誰」正是 ADR-0001 已拒絕的那類代價 |

### C 類：明確不吸納

- **付費牆與會員分級**（Web カタログ 列印為 Gold 限定、CiRCLES 需 Gold、コミマップ 免費上限 5 攤）——[ADR-0001](../adr/0001-adopt-webcatalog-patterns-selectively.md) 已否決。本次盤點反而強化這個決定：**外部服務把最有價值的離線輸出功能鎖在付費層，這正是本專案的空位**。
- **只有顏色、沒有名稱的收藏分類**——ADR-0001 已否決。
- **圖磚／圖片式底圖**——[ADR-0008](../adr/0008-static-public-reading-path.md)，且會同時廢掉 A4 的座標優勢。
- **使用者互相回報場內壅塞**（Comi Comi、Stroly）——需要即時伺服器與使用者定位，資料可信度不可控，且與 ADR-0002 的隱私姿態相反。
- **AR、電子集章、實境解謎**（Popworld）——與 PRODUCT.md「不做成活動行銷頁」的定位相反。
- **虛擬會場與場內結帳**（pictSQUARE）——不同產品，不是功能。

## 待查證

1. **Spotgram 的正確身分**——需要網址或截圖。在此之前本文不對它下任何判斷。
2. 本文所有條目都**未經操作驗證**。要升級成實地紀錄，需在可連外的環境重跑，並依既有慣例另開文件、註明日期，不修改本文。
3. CircleMap 的清單匯入格式（是否即 Web カタログ 的 CSV）未確認——這關係到 B1 是否已有事實標準可沿用。
4. Web カタログ CSV 的實際欄位未取得，無法與[資料匯入契約](../contracts/data-import.md)的 CSV v1 對照。

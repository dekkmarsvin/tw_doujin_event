# 地圖 authoring

把配置圖辨識成向量 layout、人工微調，成為候選活動的地圖草稿，經審閱後匯出為公開靜態快照。

**地圖畫在[主辦單位工作區](../contracts/organizer-workspace.md)。** 候選活動的每一組「活動日 × 場館空間」各建立一份地圖草稿，從空白或描摹起點開始。這實現了 [ADR-0038](../adr/0038-authoring-moves-to-the-control-surface-local-stays-as-backup.md) 決策第 3 點。

本機曾經有一套獨立的 `/editor` authoring 環境，寫入本機 D1 再以 `map:snapshot` 匯出。它已依 [ADR-0049](../adr/0049-the-local-authoring-backup-is-withdrawn.md) 移除：實際共用的只有 `MapLayoutEditor` 一個 component，其餘是一整套為它獨存的 build 與持久化堆疊，而那條備援路徑從未被驗證過。控制面不可用時的復原路徑改為直接編輯 data repository 中的靜態快照。

`/circle` 的貢獻面板仍只服務已公開的活動：它建立草稿的唯一入口是「從目前公開地圖建立私人草稿」（`app/circle-portal/map-contribution-panel.tsx`）。

**讀者介面（`index.html`）不得出現檔案欄位、管理入口或寫入 route**；讀取失敗只說明公開資料錯誤，不提供管理修復入口。這條約束只約束讀者介面。`circle.html` 與 `organizer.html` 是自始分離的獨立 entry（`vite.pages.config.ts`），它們在身分驗證後方提供檔案上傳與管理入口，那是 [ADR-0033](../adr/0033-map-contributions-use-admin-granted-roles-and-private-revisioned-drafts.md) 的既有機制，不是本條的例外。見 [ADR-0038](../adr/0038-authoring-moves-to-the-control-surface-local-stays-as-backup.md) 決策第 2 點。

> 2026-08-28 修訂。本段原文為「**這是受信任維護者的本機工作，不是產品功能。** 公開 Pages 介面不得出現檔案欄位、管理入口或寫入 route」。該無條件措辭自 #72／#73 落地起即與現況不符——`/circle` 早已有檔案上傳與管理入口——並且會擋住 ADR-0035 選項 B。依 ADR-0038 限縮為只約束讀者介面。

地圖的資料不變量與前台契約見[活動地圖契約](../contracts/event-map.md)。

## 流程

### 1. 開啟工作區

```bash
npm run dev:portal
```

以 Organizer 身分登入 `/organizer`，開啟候選活動的「地圖」區。地圖區需要攤位匯入已完成，因為候選地圖的 `allowedBoothCodes` 與 `requiredBoothCodes` 都由該 scope 實際匯入的攤位代碼推導（[`resolveCandidateAuthoringScope()`](../../app/event-authoring-scope.ts)）。

每一組「活動日 × 場館空間」各一份地圖草稿；缺任何一份在驗證時是 error，不是 warning。

### 2. 辨識

從該活動 data repo 或受信任的本機來源選擇原始配置圖。原圖不複製到程式 repo。

`recognizeMapTemplate(event.mapTemplate, imageData)` 依活動定義分派辨識 adapter，回傳 `MapRecognitionReport`。**辨識完全在瀏覽器內執行**（canvas `getImageData` 取像素），沒有伺服器端相依。FF47 adapter 負責：

- 從格線辨識 A–V 縱向排與 W 橫向排。
- 依 FF47 編號規則產生 slot：A 為 01–22；B–V 為 01–44；W 為 01–42。
- 從實心黑色元件辨識柱子，**保存矩形尺寸**而非降為單一點。
- 從紅色箭頭辨識出入口；上側為出口、下側為入口。
- 回傳信心、警告與完整向量 layout。

**企業攤與舞台不自動辨識**，必須在送審前手動新增。沒有辨識器的新版型從空白起點開始，改用下方的框選建立排段與手動描繪。

### 3. 預覽對照

原圖與向量結果並列。摘要先呈現一般結構辨識信心、排數、攤位格、柱子與出入口。原圖**只在此階段**作比較用。

重新上傳配置圖時，既有手動區域依新圖片尺寸等比例保留，並要求再次確認。

### 4. 細部編輯

編輯畫布提供 100% 至 400% 檢視縮放、原生捲動、倍率重設與聚焦選取。

**參考圖不跟著地圖存檔。** 底圖只留在瀏覽器這一次的作業中，儲存的地圖只有向量 layout，所以重新開啟已儲存的地圖要接著描時，得再放一次參考圖。編輯器開著的時候，工具列的上傳按鈕會顯示「上傳參考圖」，**只把圖片放到現有攤位底下，不動地圖內容**；編輯器沒開時它顯示「上傳配置圖並編輯」，才會用圖片建立新的 layout（有辨識器就辨識，沒有就依圖片尺寸開一張空白底圖）。同一個檔案可以連續選第二次。

- **「新增排／排段」在原圖上框出一段攤位**：先填排標籤、代碼前綴、**起始編號與結束編號**（配置圖上印的就是這兩個數字，例如某欄是 01–26 就填 1 與 26，格數由兩者相減得到）、補零位數、方向與**編號起點**（直排：上→下／下→上；橫排：左→右／右→左），然後直接在底圖拖曳框住一段連續攤位。**放開滑鼠就建立**，沒有另外的確認按鈕——框選本身已經說完攤位需要的一切，要檢查的東西不論如何都在畫布上。**座標與每格寬高由框選結果算出**，一般流程不必輸入。
  - 框選矩形就是這一段的**總外框**：直排 N 格時每格高為框高的 N 分之一、寬即框寬，橫排反之。每格由相鄰切線構成，因此**連續攤位無縫相接**，不會因為中心間距與格子尺寸兩套數值不匹配而出現縫隙或重疊；切線一律由框的起點加上總長的 i/N 算出，長排也不會累積浮點誤差。
  - 沒填排標籤時不會開始框選，因為放開滑鼠就已經建立，沒有第二次機會補。
  - 方向取框的長軸；換軸時編號起點回到該軸的第一端。排標籤與代碼前綴是任意字串，因此地支（`子`、`丑`…）或 `商` 這類區段不需特殊處理；前綴留空則沿用排標籤。
  - **建立後這一段仍被框著，四角把手可以整段重新分割**，並對其他已放好的攤位吸附（按住 Alt 暫停）。這是修正整排大小的方式：不必逐格調整，也不必整排刪掉重放。**點任何一格攤位就改抓它所在的那一段**，因此先前放好的排段隨時可以再調整；一段是指彼此貼齊的連續攤位，走道兩側算兩段。
  - 建立後仍可改**方向**（同一個框沿另一軸重新分割，代碼不變）與**編號起點**（代碼整段反過來，矩形不動），不必復原重畫。
  - 建立後面板不關閉：排標籤、前綴、補零位數、方向與編號起點都留著，**起始編號與結束編號各自加上剛才的格數**，可以直接框下一段。K51 的 A 排因此是：填 1 與 12 後框第一段；面板自動跳到 13–24，把結束編號改成 32 再框第二段；面板跳到 33–52，把結束編號改成 44 再框第三段。
- **一個排標籤可以有多個排段**：填入既有排標籤時，這一段會**併入該排**，面板顯示「將加入既有 B 排（目前 N 格）」；填新標籤才建立新排。CWT*K51 的 B 區左右兩欄、被通道切成三段的 A 區、以及一排背對背的兩面攤位，都是同一個排標籤下的數個排段。**排的方向取第一段的方向**，所以同一排的各段方向不一致時，排標籤會落在錯的一軸。同一場館的不同活動日攤位範圍不同（K51 第一天雙欄是 01–26／27–52，第二天是 01–24／25–48），每一天各自框選即可，工具不綁定任何固定格數。
- **背對背的兩面用相反的編號起點**：同一排上下（或左右）兩面編號方向相反時，兩段用同一個排標籤、不同的起始編號與相反的編號起點即可，不需要另一套規則。編號起點只影響代碼發放的順序，不改變矩形，也不寫進 `EventMapLayout`。
- 拖曳過程中會即時把框切成 N 格畫在畫布上，放開才寫進 layout；跨排重複的攤位代碼與結束編號小於起始編號都會擋下並說明原因。重複的排標籤不再是錯誤，而是併段。
- **編輯畫布會畫出排標籤**（A、B、C…W），位置與讀者看到的完全相同（同一個 `rowLabelAnchor()`），因此排標籤落在哪一軸、對不對得上原圖，在編輯時就看得到。標籤跟著整排走，不是每段一個。
- **錨點推算（進階設定）**：這是**傾斜校正工具**，只適用**同一條等距直線排段**——原圖有輕微旋轉、掃描歪斜，或很難精確框到頭尾時使用；**不得跨走道或跨平行欄**，那些情況請分開框選。展開「進階設定」後按「開始標記錨點」，於畫布空白處點選三格以上的中心，並在清單填入該格在這一排的編號（可不相鄰、不依序，例如第 1、5、12 格）。工具以最小平方法對兩軸擬合直線，外推出最低到最高編號之間的每一格，並顯示格數、起始編號與**最大偏差**——偏差大代表某個錨點點在別格上，或錨點根本不在同一條線上（例如分屬兩欄），應先修正再推算。三個是最少能互相矛盾的數量，兩個只能決定一條線而無法平均掉點選誤差。推算只給中心與格數，外框仍用進階設定的每格寬高，所以它不保證無縫。
  - 進階設定同時保留**用起點與終點的中心座標建立**的舊流程，供斜排或刻意留間距的排段使用。
  - **推算結果一律是草稿**：草稿以虛線畫在畫布上，逐格列出並各自有確認勾選框，**預設全部未確認**。未確認的格以灰色虛線畫出、已確認的以綠色實線畫出，兩者都在畫面上，才能對著原圖判斷該留哪幾格——外推會產生錨點之間本來不存在的格子（例如中間其實是通道），預設勾選會讓確認步驟形同虛設。只有勾選確認的格會寫進 layout，一格都沒確認時「加入確認的 N / M 格」不可按。草稿不存在於 `EventMapLayout` 裡，因此未確認的格子在結構上就不可能進入送審內容——這是位置關係，不是額外的旗標。
  - 改動排標籤、代碼前綴、每格寬高、補零位數等任一欄位，或新增、移除、改動任一錨點編號，都會**丟棄既有草稿**；改變畫布尺寸時錨點與其他元素一起依比例縮放，草稿同樣丟棄，必須重新推算，避免畫面顯示新值卻寫入舊值。關閉「新增排／排段」面板會一併結束錨點標記，畫布隨即恢復多選與拖曳。
  - 推算只決定端點與格數，實際產生 slot 仍由 `generateRowSlots` 負責，代碼與唯一性檢查與手動建立完全相同。推算邏輯在 `app/map-layout-editor-geometry.ts`，不依賴任何版型辨識器，可用於沒有辨識器的新版型。
- inspector 的排清單可改名、改方向或移除整排。
- **「手動畫攤位」逐格描繪**：輸入排標籤與起始代碼後在畫布拖曳出攤位外框，一次一格，代碼自動遞增，適合間距不規則、等距產生會對不上的段落。標籤欄有既有排標籤的下拉建議；填既有標籤即併入該排。
- 可拖曳或輸入座標調整一般攤位、柱子與出入口。**場館外框從外框線拖曳**，避免填滿整張圖時吃掉空白處的點擊。
- 可新增、命名、分類、縮放或移除企業攤、舞台及其他非一般攤位區。
- 選取一般攤位、柱子、非一般攤位區或場館外框後，物件四角顯示直接縮放把手。
- **多選**：Shift 點選加選或取消單一元素；在空白處拖曳框選範圍內的所有元素，按住 Shift 拖曳則併入既有選取。選超過一個元素時，四角把手改為框住整組，縮放會把整組從原本的外接矩形映射到新的外接矩形，內部間距按比例保留。**整組縮放維持長寬比**：長寬各自依自己的邊長換算時，兩排攤位那種細長選取會讓同一個手勢在兩軸產生差好幾倍的倍率，格子忽高忽扁，而且兩軸還會各自先撞到畫布邊界或最小值；改成兩軸共用一個倍率（把位移投影到選取範圍自己的對角線），格子就維持原本的形狀，放大縮小也是線性的。要單獨改一個元素的寬或高，選取單一元素或改用 inspector 的寬／高欄位。
- **批次操作**：多選後可一起拖曳、以方向鍵微調，或用 inspector 的「自動對齊」與靠左／靠右／靠上／靠下對齊。整組共用同一位移，因此碰到畫布邊界時整組一起停下，不會壓扁彼此間距。一次批次操作是一個復原步驟。
  - **對齊是往該側靠攏，不是疊在同一條線上**：每個元素往指定的那一邊滑，滑到整組外接矩形的那一側邊界、或撞到已經定位的元素為止。另一軸完全不動，所以直排仍是直排、橫排仍是橫排；改變的是間距收攏，而且**兩個攤位不會疊在一起**。**同不同一條線，以半格為界**：兩個元素在另一軸的重疊超過較小那個的一半才算同一條線，會依序緊貼排好；重疊不到一半的就是並排，彼此擋不住，因此一排攤位按靠上就是單純的靠上對齊。手繪描出來的兩直排常常互咬幾個單位，以前只要咬到一點就被當成同一直排，整塊會被接成一條上下錯開、兩倍長的鏈。原本互相重疊的一組攤位被推開後會比原本的外接矩形長，末端可以超出該矩形，只有畫布邊界會擋下它。
  - **自動對齊**：一鍵把手繪描出來的一塊整理成格狀——先把每格改成組內最多元素採用的大小（兩種大小一樣多時取較大的，每格以自身中心縮放），再依「畫的時候本來在哪一直排」排成格線：從整組左上角起算，每一直排由上而下一格接一格，直排與直排緊貼排開。分排同樣以半格為界，且是跟左右相鄰那格比而不是跟排頭比，所以描歪的一直排仍算同一排。兩排直排一起選取後按一次就會變成緊密貼合、不重疊的格狀；出入口沒有大小、在格狀裡沒有位置，維持不動，也不會把整塊拉到它那邊（格線的起點只看有大小的元素）。
- **複製整排**：選取一格或多格攤位後，inspector 立刻出現「新排標籤」欄位，按「複製選取的 N 格」即完成複製，供對排配置使用。新的一排緊貼原本那組的旁邊：直排往側邊複製、橫排往下方複製，靠到畫布邊界時改往另一側，因此不會疊在原本的攤位上。排標籤留空則沿用原標籤。重複的排標籤與攤位代碼會自動加上數字後綴，代碼隨新排標籤更名，因此結果不會與既有代碼衝突。複製後新排即為選取狀態，直接拖曳就能移到實際位置。
- **關閉編輯器**：地圖有改過而尚未儲存時，「關閉編輯器」會先問要不要儲存，可選儲存並關閉、放棄或取消。沒有改過就直接關閉。切換地圖分頁、按「空白畫布」或從同空間複製仍會直接丟掉未儲存的內容（編輯器開著時上傳圖片只是換參考圖，不會丟掉地圖）。
- inspector 上方的「畫布寬」「畫布高」改變座標空間，既有排、柱子、非一般攤位區與出入口依比例保留。
- **吸附**：拖曳四角縮放時對同類元素吸附（攤位對攤位、柱子對柱子、企業攤對企業攤），移動時只有企業攤對企業攤吸附。距離 8 個螢幕像素內且另一軸至少重疊四分之一時，自動吸附最近的相對邊並顯示對齊導引線。**按住 Alt 暫停吸附。**
- 方向鍵移動 1px，Shift + 方向鍵移動 10px；多選時整組一起移動。畫布有焦點時按 `Delete`（或 `Backspace`）移除選取的元素，等同 inspector 的移除按鈕：場館外框不會被移除，排上最後一格被移除時整排一併消失。
- **逐步復原**：工具列的「復原」與「重做」（`Ctrl`／`Cmd` + `Z`，加 `Shift` 或 `Ctrl` + `Y` 重做）可回到任一中間狀態，不必整份還原。快捷鍵在 inspector 有焦點時同樣有效，但文字欄位內保留瀏覽器原生的復原。
  - **一次手勢算一步**：一次拖曳或縮放、一段連續同方向的方向鍵微調、同一欄位的連續輸入各自合併成單一步驟；改變方向、換欄位、放開方向鍵或結束拖曳都會結束該步驟，下一次操作另起一步。
  - 復原後再編輯會捨棄可重做的分支。
  - 歷史只保存最近 `LAYOUT_HISTORY_LIMIT`（50）份 layout，**不保存原始圖位元組**。超出上限的最舊步驟會被丟棄。
  - 重新辨識圖片、改用空白地圖或按「還原本次編輯」是整份替換 layout，不是編輯步驟，歷史會從新的 layout 重新開始。
- 720px 以下貼底並改為單欄預覽，主要發布動作固定在工作面板底部。此規則不增加任何公開 Pages route。

### 5. 保存為候選 revision

地圖草稿以 `PUT /api/organizer/events/:candidateId/maps/:draftId` 保存，成為候選活動的一份 revision。每份已保存地圖必須通過與正式 validation 相同的攤位覆蓋、未知攤位、重疊與幾何規則。

**候選活動的地圖可以含沒有社團的攤位格。** 配置圖畫的是整個場地，包含沒賣掉的攤位，而那些格子沒有任何匯入列可以指認；因此候選活動的 `unknown_booth` 是 warning 而非 error（`allowsUnallocatedBooths`）。`missing_booth`、`overlap` 與幾何錯誤不受影響。

人工繪製沒有 template 完整性規則可擋，**逐格與官方攤位清單的核對是人工責任**。

### 6. 驗證、送審與核准

依[主辦單位工作區契約](../contracts/organizer-workspace.md)：`POST …/validate` → `POST …/preview` → `POST …/submit`（僅 Owner，需 fresh session），再由全域管理者以 `POST /api/admin/organizer/events/:candidateId/review` 核准。

送審會固定一份 `organizer-submission-snapshot/1`，包含每份地圖內容，並以其 SHA-256 作為 approval hash。

### 7. 發布

核准建立一筆 `queued` 發布工作。**發布尚未啟用**，三處各自 fail closed，見該契約的[發布邊界](../contracts/organizer-workspace.md#發布邊界)。

在發布啟用前，公開快照仍由人工在 data repository 中 review、提交並推送，再依[社團與活動資料更新](./catalog-data-update.md)更新 pin。

**靜態快照是公開資料的唯一真相。** 未經 review 的候選內容不會因 Pages 部署而公開。
